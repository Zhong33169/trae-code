## 1. 产品概述

展会观众预约单管理系统——为展会主办方提供观众预约单全生命周期管理，覆盖登记员发起/补正、审核主管办理、主办方复核归档三段工作流，确保流程不可越权、证据不可缺失、状态不可回退。

- 目标用户：展会主办方日常运营团队，分登记员、审核主管、复核负责人三岗
- 核心价值：流程铁壁——后一岗位无法替前一岗位补流程，缺证据单据无法推进，重复/异常单据在页面和接口双线拦截

## 2. 核心功能

### 2.1 用户角色

| 角色 | 登记方式 | 核心权限 |
|------|----------|----------|
| 观众预约登记员 | 演示账号登录 | 发起观众预约单、补正被退回的预约单 |
| 观众预约审核主管 | 演示账号登录 | 审核预约单（通过/退回），不能发起或补正 |
| 展会主办方复核负责人 | 演示账号登录 | 复核已审核单据并归档，不能审核或发起 |

### 2.2 功能模块

1. **预约单工作台（首页）**：预约单队列列表 + 侧边证据面板 + 角色切换 + 筛选
2. **预约单详情办理页**：单据详情、操作按钮（按角色显示）、证据查看、版本追踪
3. **批量操作面板**：批量审核/复核、结果反馈、异常提示

## 3. 核心流程

观众预约单从发起到归档需严格按三岗顺序流转，任何岗位不可越权操作前一环节。

```mermaid
flowchart TD
    "登记员发起预约单" --> "状态: 待审核"
    "状态: 待审核" --> "审核主管审核"
    "审核主管审核" -->|通过| "状态: 待复核"
    "审核主管审核" -->|退回| "状态: 已退回(补正)"
    "状态: 已退回(补正)" --> "登记员补正"
    "登记员补正" --> "状态: 待审核"
    "状态: 待复核" --> "复核负责人复核"
    "复核负责人复核" -->|归档| "状态: 已归档"
    "复核负责人复核" -->|退回| "状态: 已退回(审核)"

    "登记员发起预约单" -.->|越权尝试| "后端拦截: 角色不匹配"
    "审核主管审核" -.->|缺证据| "后端拦截: 证据链不完整"
    "复核负责人复核" -.->|旧版本| "后端拦截: 版本冲突"
```

**越权拦截规则：**
- 登记员不能审核或复核
- 审核主管不能发起、补正或复核
- 复核负责人不能发起、补正或审核
- 后端对每一步操作校验角色、状态、证据、版本，返回具体拦截原因

**证据链要求：**
- 观众预约：预约登记表单、预约时间戳
- 入场核销：核销记录、核销时间
- 数据回收：回收确认、回收时间
- 缺少任一证据，审核/复核环节将被拦截

## 4. 用户界面设计

### 4.1 设计风格

- 主色调：深蓝 #1e3a5f + 琥珀色 #d97706 强调
- 按钮风格：圆角 6px，主按钮实色填充，次按钮描边
- 字体：Noto Sans SC（正文 14px，标题 18-24px）
- 布局：左侧主队列 + 右侧证据面板，详情页全屏弹窗
- 图标：lucide-react 图标库

### 4.2 页面设计概览

| 页面名称 | 模块名称 | UI元素 |
|----------|----------|--------|
| 预约单工作台 | 预约单队列 | 卡片列表、状态标签(彩色)、批量复选框、排序 |
| 预约单工作台 | 证据侧边栏 | 三列折叠面板(预约/核销/回收)，缺失项红色标记 |
| 预约单工作台 | 角色切换器 | 顶部头像+角色名，下拉切换 |
| 预约单工作台 | 筛选器 | 状态下拉、日期范围、搜索输入框 |
| 预约单详情 | 单据信息 | 表单展示(只读)、版本时间线、操作日志列表 |
| 预约单详情 | 操作区 | 底部固定操作栏，按角色灰显不可用按钮 |
| 预约单详情 | 证据面板 | 证据卡片列表，缺失项红色边框+提示文字 |
| 批量操作 | 批量操作栏 | 浮动底栏，已选数量、操作按钮、结果弹窗 |

### 4.3 响应式设计

- 桌面端优先（1280px+），证据侧边栏在窄屏下可折叠
- 触控适配：按钮最小 44px 点击区域

### 4.4 样例数据策略

准备以下暴露问题的样例预约单：
1. **重复补录单**：同一观众信息被登记员提交两次，后端应拦截重复
2. **缺证据单**：预约单缺少入场核销记录，审核主管审核时应被拦截
3. **覆盖结果单**：两个审核主管同时操作同一单据，后者应因版本冲突被拦截
4. **错状态单**：已归档单据尝试再次审核，后端应拦截
5. **越权操作**：复核负责人尝试发起预约单，后端应拦截
6. **旧版本单**：登记员基于旧版本补正，后端应检测版本冲突
