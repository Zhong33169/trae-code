# 景区运营团队预约单系统

景区运营公司异常申诉复核团队预约单管理系统。

## 系统概述

本系统围绕景区团队预约单的全生命周期管理，涵盖团队预约、票务核销、入园统计三大流程，支持异常申诉的提交、受理、驳回补正、再次提交等完整闭环。

### 岗位角色

| 岗位 | 用户名 | 密码 | 职责 |
|------|--------|------|------|
| 票务专员 | zhangsan | 123456 | 团队预约单票务核销 |
| 现场调度 | lisi | 123456 | 入园统计、提交异常申诉 |
| 景区经理 | wangwu | 123456 | 归档、申诉复核处理 |

### 核心流程

```
团队预约 → 票务核销(票务专员) → 入园统计(现场调度) → 归档(景区经理)
                                      ↓
                                  异常申诉
                             ↗        ↓        ↘
                        提交 → 受理 → 驳回补正 → 再次提交
                             ↘        ↓        ↙
                                申诉通过 / 申诉驳回
```

### 状态流转规则

- **票务专员** 只能处理「待票务核销」状态的预约单，推进到「已核销待入园」
- **现场调度** 只能处理「已核销待入园」状态的预约单，推进到「已入园待归档」
- **景区经理** 负责归档和申诉处理

## 技术栈

- **前端**: React 18 + Vite + React Router
- **后端**: Python Flask + SQLAlchemy
- **数据库**: SQLite（本地文件）
- **端口**: 前端 3004，后端 8004

## 快速开始

### 1. 环境要求

- Python 3.8+
- Node.js 16+
- npm 或 yarn

### 2. 后端启动

```bash
cd backend

# 安装依赖
pip install -r requirements.txt

# 初始化数据库（创建表 + 样例数据）
python init_db.py

# 启动服务
python app.py
# 或指定端口
BACKEND_PORT=8004 python app.py
```

后端服务启动后访问: http://localhost:8004/api/health

### 3. 前端启动

```bash
cd frontend

# 安装依赖
npm install

# 启动开发服务器
npm run dev
# 默认端口 3004
```

前端访问地址: http://localhost:3004

### 4. 修改端口

**修改后端端口**:
```bash
# 方式一：环境变量
BACKEND_PORT=8004 python app.py

# 方式二：修改 config.py 中的默认值
```

**修改前端端口**:

编辑 `frontend/vite.config.js` 中的 `server.port`。

同时需要修改 `backend/app.py` 中 CORS 的 origins 配置。

## API 接口

### 认证

- `POST /api/auth/login` - 登录
- `POST /api/auth/logout` - 登出
- `GET /api/auth/me` - 当前用户信息

### 预约单

- `GET /api/orders/queue` - 我的待处理队列
- `GET /api/orders/all` - 全部预约单
- `GET /api/orders/:id` - 预约单详情
- `POST /api/orders` - 创建预约单
- `POST /api/orders/:id/transition` - 状态流转
- `GET /api/orders/stats` - 统计数据

### 申诉

- `POST /api/appeals` - 提交申诉
- `GET /api/appeals/:id` - 申诉详情
- `POST /api/appeals/:id/accept` - 受理申诉
- `POST /api/appeals/:id/reject` - 驳回补正
- `POST /api/appeals/:id/resubmit` - 再次提交
- `POST /api/appeals/:id/approve` - 申诉通过
- `POST /api/appeals/:id/deny` - 申诉驳回
- `GET /api/appeals/list` - 申诉列表

### 后端校验规则

状态流转时后端会校验：
1. **当前处理人角色** - 角色是否有权限处理该状态
2. **状态流转合法性** - 当前状态是否允许流转到目标状态
3. **版本号** - 乐观锁，防止并发修改冲突
4. **必填证据** - 目标状态所需的证据是否齐全
5. 校验不通过时**保留原状态**并写入操作记录

## 演示指南

### 场景一：正常流程走完全程

1. 登录 **zhangsan（票务专员）**
   - 查看「我的队列」，找到 TM20260611001
   - 点击进入详情，执行「票务核销」
   - 选择已有的证据，提交

2. 登录 **lisi（现场调度）**
   - 队列中看到刚才的单子已流转过来
   - 执行「入园统计」，补充入园记录证据

3. 登录 **wangwu（景区经理）**
   - 队列中看到该单
   - 执行「归档」，补充结算单证据
   - 流程完成

### 场景二：异常申诉全流程

1. 登录 **lisi（现场调度）**
   - 找到一个已核销的预约单
   - 点击「提交异常申诉」
   - 填写申诉理由，提交

2. 登录 **wangwu（景区经理）**
   - 队列中看到申诉中的预约单
   - 进入详情，查看申诉内容
   - 点击「驳回补正」，填写驳回原因

3. 登录 **lisi（现场调度）**
   - 找到该预约单
   - 点击「再次提交申诉」，补充材料说明

4. 登录 **wangwu（景区经理）**
   - 受理申诉
   - 点击「申诉通过」或「申诉驳回」
   - 选择申诉通过后的预约单状态

### 场景三：角色权限校验

- 用票务专员账号尝试操作已核销的单子 → 应无操作按钮
- 用现场调度账号尝试归档 → 应无操作按钮
- 验证岗位间不能越权操作

### 场景四：版本冲突测试

1. 两个窗口同时打开 TM20260611010 的详情
2. 第一个窗口执行操作
3. 第二个窗口再执行操作 → 应提示版本冲突
