# 体育场馆扫码核验场地订单系统

## 项目概述

一个完整的体育场馆场地订单扫码核验系统，实现从订单登记、补正、审核到复核归档的全流程处理。

## 技术栈

- **前端**: React 18 + TypeScript + Vite + Zustand + React Router
- **后端**: NestJS + TypeScript + Class Validator
- **端口**: 前端 3107，后端 8107

## 快速启动

## 核心功能

### 1. 扫码核验
- 支持二维码有效性校验
- 无效码、重复码、非当前处理人等场景的详细错误说明
- 材料缺失检查
- 并发处理锁检测

### 2. 订单流程
```
待登记 → 提交登记 → 待审核 → 审核通过 → 待复核 → 复核通过 → 已归档
               ↓            ↓                       ↓
            待补正 ← 要求补正                    已驳回
               ↓
            提交补正 → 待审核
```

### 3. 权限控制
- 每个岗位只能处理对应状态的订单
- 非当前处理人无法操作订单
- 越权操作返回详细错误信息

### 4. 并发控制
- 处理订单时自动加锁
- 两个页面同时提交时，后提交的会被拒绝
- 锁自动释放机制

### 5. 审计日志
- 所有操作都有完整的审计记录
- 记录操作人、时间、动作、意见、状态变更
- 不可篡改的操作留痕

### 6. 统计面板
- 待补正、待审核、待复核数量统计
- 数字可点击跳转到对应筛选列表
- 我的待办、已归档、已驳回统计

### 7. 批量处理
- 支持同状态订单批量处理
- 处理意见必填
- 成功/失败结果分开展示，失败原因详细说明

## API 接口

### 扫码相关
- `POST /api/scan/validate` - 验证二维码
- `POST /api/scan/scan` - 扫码核验

### 订单相关
- `GET /api/orders` - 获取订单列表
- `GET /api/orders/statistics` - 获取统计数据
- `GET /api/orders/:id` - 获取订单详情
- `GET /api/orders/:id/audit-logs` - 获取审计日志
- `POST /api/orders` - 创建订单
- `PUT /api/orders/:id/process` - 处理订单
- `POST /api/orders/batch-process` - 批量处理

### 用户相关
- `GET /api/users/me` - 获取当前用户信息
- `GET /api/users/mock` - 获取测试用户列表
- `GET /api/users/roles` - 获取角色列表

## 设计特点

1. **领域驱动设计**: 清晰的分层架构，业务逻辑与技术实现分离
2. **状态机**: 严格的订单状态流转控制，防止非法操作
3. **可观测性**: 完整的审计日志，操作全程可追溯
4. **用户友好**: 错误提示详细，给出具体原因和解决建议
5. **权限最小化**: 每个岗位只能看到和处理职责范围内的订单
6. **数据一致性**: 乐观锁 + 悲观锁结合，防止并发冲突
7. **可配置**: 端口、CORS 等通过环境变量配置，不写死在代码中
