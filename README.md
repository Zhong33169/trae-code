# 航空地服 - 离线台账回填值机记录系统

面向航空地服的值机记录离线台账回填管理系统，覆盖值机记录登记、过程核验、复核归档全流程，支持多角色权限控制和异常审计追踪。

## 技术栈

- **前端**：Angular 17 + Vite，端口 `3001`
- **后端**：Go + Echo，端口 `8001`
- **数据库**：SQLite（seed 数据已内置）

## 快速启动

### 1. 启动后端（端口 8001）

```bash
cd backend
go mod tidy
go run main.go
```

后端启动后会自动初始化 SQLite 数据库并导入 seed 数据。

### 2. 启动前端（端口 3001）

```bash
cd frontend
npm install
npm start
```

访问 `http://localhost:3001` 即可使用。

## 测试账号（密码统一为 `123456`）

| 用户名 | 角色 | 权限说明 |
|--------|------|---------|
| `initiator1` | 发起岗 | 登记值机记录、重新发起退回的记录 |
| `handler1` | 办理岗 | 核验材料、处理退回、填写结果 |
| `reviewer1` | 复核岗 | 复核归档、退回修改 |
| `admin` | 管理员 | 全部权限，可在顶部切换角色体验 |

## 业务流程

```
待发起(pending) → 办理中(processing) → 已核验(verified) → 已归档(archived)
                    ↓                     ↓
                已退回(returned)       已退回(returned)
                    ↓
              重新发起 → 办理中
```

- **发起岗**：在列表页或登记页创建记录，状态变为 `办理中`
- **办理岗**：核验材料完整性，通过则状态变为 `已核验`，不通过则退回并填写退回原因
- **复核岗**：对已核验记录进行复核，通过则 `已归档`，不通过则退回
- **退回记录**：发起岗可重新发起，走一遍流程

## 系统功能

### 值机记录列表
- 支持按状态、异常标记、航班号、批次号、旅客/证件搜索
- 不同角色显示不同操作按钮（后端同时校验权限，前端仅做展示）
- 管理员/办理岗/复核岗支持批量操作（批量核验、归档、退回）
- 批量操作结果逐条展示，成功/失败一目了然

### 值机记录详情
- 完整展示基本信息、附件、处理流程时间线、审计日志
- **附件管理**：上传/删除附件（PDF、JPG、PNG 等）
- **处理结果**：办理岗填写核验结果
- **审计备注**：复核岗填写归档备注
- **退回原因**：退回时必填，展示在详情页醒目位置
- **一致性问题检测**：系统自动检测重复批次和状态不一致，阻止归档

### 审计日志
- 每一条操作（包括失败）都会写入审计日志
- 「审计日志」菜单专门列出所有失败记录，可追溯：
  - **谁**：操作人姓名
  - **什么时候**：精确到秒的时间戳
  - **为什么失败**：失败原因详情

#### 3. 退回单
- **ID: 7**，旅客：冯雪，航班 CA8888

- 详情页红色块显示退回原因

- 系统自动标记异常

#### 5. 状态不一致（拦截归档）

- 系统自动检测到线上线下状态不一致并标记异常

### 📦 批量操作验收
- 使用 `handler1`（办理岗）登录
- 在列表页勾选多条「办理中」状态的记录，选择「批量核验」
- 或使用 `reviewer1`（复核岗）勾选「已核验」记录批量归档
- 或选「批量退回」（需填写退回原因）
- 结果会逐条显示：成功 ✅ / 失败 ❌ + 原因

## 关键工程实现

### 后端架构（Go + Echo）
- `main.go`：服务入口，CORS 放行 `http://localhost:3001`
- `database/`：SQLite 初始化、schema、seed 数据
- `middleware/auth.go`：JWT 认证 + 角色权限中间件
- `handlers/checkin.go`：核心业务逻辑
  - 值机记录 CRUD
  - 状态机校验（`StatusTransitions` 定义合法流转）
  - 角色动作校验（`RoleAllowedActions` 定义各角色可执行动作）
  - 重复批次检测（`detectDuplicates`）
  - 线上线下状态不一致检测（`detectStatusInconsistency`）
  - 批量处理逐条返回结果
  - 审计日志写入（含失败原因）
- `handlers/attachment.go`：附件上传/删除 + 审计日志查询

### 前端架构（Angular + Vite）
- `src/app/pages/login/`：登录页
- `src/app/pages/list/`：列表页（筛选、批量、角色差异化按钮）
- `src/app/pages/detail/`：详情页（附件、时间线、退回原因、审计日志、快捷操作）
- `src/app/pages/create/`：登记页（表单验证 + 实时一致性检测）
- `src/app/pages/audit/`：失败记录审计追溯
- `src/app/services/`：认证服务（`AuthService`）+ API 服务（`CheckinService`）+ 拦截器

### 端口配置
- 前端 Vite：`server.port = 3001`，`/api` 代理到后端 `http://localhost:8001`
- 后端 Echo：监听 `:8001`，CORS 只放行 `http://localhost:3001`
- 前端 API 请求地址：直接指向 `http://localhost:8001/api`

### 数据库文件
- SQLite 文件路径：`backend/database/app.db`
- 首次启动自动执行 `database/schema.sql` 建表
- 若 `users` 表为空则自动执行 `database/seed.sql` 导入测试数据
- 删除 `app.db` 后重启即可重置数据库
