# 消防救援站-节点超时追踪消防隐患单系统

基于 Preact + Vite + Go + Chi + SQLite 构建的消防隐患单节点超时追踪管理系统。

## 功能特点

- **隐患单全生命周期管理**：从隐患上报、分派转办、整改通知、复查销项到最终确认闭环
- **三级岗位权限控制**：消防文员 → 防火监督员 → 站点负责人，各自可见字段和操作按钮不同
- **状态流转**：待分派 → 已转办 → 已回访，后端驱动，前端一致
- **节点超时追踪**：5 个处理节点各有时限，超时自动标记，处理时强制留下原因和后续措施
- **数据一致性**：列表、详情、批量状态、统计和操作记录均以后端为准，自动定时刷新
- **详细操作记录**：每次状态/节点变更均留痕，可追溯

## 岗位与权限

| 岗位 | 角色标识 | 可见范围 | 可执行操作 |
|------|----------|----------|------------|
| 消防文员 | `clerk` | 本人上报的隐患单 | 上报隐患单、查看详情/记录 |
| 防火监督员 | `supervisor` | 待分派、已转办及本人相关的隐患单 | 转办分派（下发整改通知）、提交整改记录、处理超时 |
| 站点负责人 | `station_chief` | 已转办、已回访的隐患单 | 复查回访、确认完成、处理超时 |

## 状态与节点

**状态（status）**：
- `pending` 待分派 — 消防文员刚上报
- `assigned` 已转办 — 防火监督员已分派，处理中
- `revisited` 已回访 — 站点负责人已复查回访

**处理节点（current_node）**：
1. `report` 隐患上报（时限 24h）
2. `assign` 分派转办（时限 24h）
3. `rectify` 整改通知（时限 72h，受整改截止日期约束）
4. `recheck` 复查销项（时限 48h，受复查截止日期约束）
5. `confirm` 确认完成（时限 24h）

## 快速启动

### 环境要求

- Go >= 1.21
- Node.js >= 18
- SQLite（go-sqlite3 驱动内置，无需额外安装）

### 1. 启动后端（端口 18010）

```bash
cd backend
go mod tidy          # 首次执行，下载依赖
go run .             # 启动服务，默认端口 18010

# 或自定义端口与数据库路径
go run . -port 18010 -db ./data/fire_hazard.db
```

首次启动会自动：
- 创建 `./data/fire_hazard.db` SQLite 数据库文件
- 建表（users, hazard_orders, hazard_reports, rectification_notices, rectification_records, recheck_records, timeout_records, operation_logs）
- 插入 6 个测试用户和 3 条样例隐患单

### 2. 启动前端（端口 30010）

```bash
cd frontend
npm install          # 首次执行
npm run dev          # 启动 Vite 开发服务器，端口 30010
```

浏览器访问：**http://localhost:30010**

前端已配置 `/api` 代理到后端 `http://localhost:18010`。

## 样例使用流程

1. **登录** `clerk01` / 123456（消防文员）
   - 点击右上角「+ 上报隐患」，填写标题、地点、等级、内容后提交
   - 隐患单进入 **待分派** 状态

2. **切换登录** `supervisor01` / 123456（防火监督员）
   - 在列表中找到刚创建的「待分派」隐患单，点击进入详情
   - 点击「转办分派」，填写整改期限（天）和整改通知内容 → 确认转办
   - 状态变为 **已转办**，节点进入「整改通知」
   - 待整改后，点击「提交整改」填写整改内容 → 节点进入「复查销项」

3. **切换登录** `chief01` / 123456（站点负责人）
   - 进入隐患单详情，点击「复查回访」，选择复查结果并填写内容
   - 状态变为 **已回访**，节点进入「确认完成」
   - 最后点击「确认完成」→ 隐患单闭环

4. **超时处理**（任一岗位）
   - 若某节点超过时限，列表和详情会显示红色「超时」标记
   - 点击「处理超时」，必须填写 **超时原因** 和 **处理措施**，可选择顺延天数
   - 处理记录会保存在「超时记录」Tab 中

5. **统计分析**
   - 左侧菜单进入「统计分析」查看总数、各状态数量、超时数量、节点分布等

## API 接口

后端基础路径：`http://localhost:18010/api`，请求需带 `Authorization: Bearer <token>`。

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/login` | 登录，返回 token 和 user |
| GET | `/me` | 获取当前用户 |
| GET | `/users` | 用户列表 |
| GET | `/statistics` | 统计数据（摘要 + 节点分布） |
| GET | `/orders` | 隐患单列表（?status=&keyword=&page=&size=） |
| POST | `/orders` | 创建隐患单（仅消防文员） |
| POST | `/orders/batch-status` | 批量查询状态（body: {ids:[]}） |
| GET | `/orders/{id}` | 隐患单详情（含所有关联记录） |
| POST | `/orders/{id}/assign` | 转办分派（仅防火监督员，待分派状态） |
| POST | `/orders/{id}/rectify` | 提交整改（仅防火监督员，整改节点） |
| POST | `/orders/{id}/recheck` | 复查回访（仅站点负责人，复查节点） |
| POST | `/orders/{id}/confirm` | 确认完成（仅站点负责人，已回访状态） |
| POST | `/orders/{id}/handle-timeout` | 处理超时（需填写原因和措施） |

接口错误返回统一格式：`{ "error": "错误信息", "code": HTTP状态码, "detail": "可选详情" }`，前端会直接展示具体错误而非通用提示。

## 数据一致性保证

1. 所有写操作均在后端**事务**中完成：更新隐患单状态 + 写入对应记录 + 写入操作日志
2. 前端列表页每 15 秒、详情页每 30 秒、统计页每 30 秒**自动刷新**
3. 列表页使用 `batch-status` 接口增量同步状态
4. 所有操作前后端均校验**当前状态/节点**是否允许执行，状态以后端为准
5. 刷新页面后数量、状态、统计完全一致（均从后端重取）
