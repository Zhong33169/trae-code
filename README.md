# 展会观众预约单管理系统

展会主办方日常使用的观众预约单全生命周期管理工具，覆盖登记员发起/补正、审核主管办理、主办方复核归档三段工作流，确保流程不可越权、证据不可缺失、状态不可回退。

## 技术栈

- 前端：React 18 + TypeScript + Vite + Tailwind CSS + Zustand
- 后端：Rust + Actix Web 4 + rusqlite
- 数据库：SQLite（本地文件）
- 前端端口：3003，后端端口：8003

## 初始化

### 前置条件

- Node.js 18+
- Rust 1.70+（含 cargo）

### 后端

```bash
cd backend
cargo build
cargo run
```

后端启动后监听 `http://localhost:8003`，首次启动自动建表并写入种子数据。

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端开发服务器启动在 `http://localhost:3003`，`/api` 请求自动代理到后端。

## 核心功能

### 三岗工作流

```
登记员发起/补正 → 审核主管审核 → 复核负责人归档
```

后一岗位无法替前一岗位操作，后端对所有操作校验角色、状态、证据、版本。

### 后端拦截规则

| 错误码 | 触发条件 | 示例 |
|--------|----------|------|
| ROLE_MISMATCH | 角色无权执行此操作 | 复核负责人尝试发起预约单 |
| WRONG_STATUS | 单据状态不允许此操作 | 已归档单据再次审核 |
| MISSING_EVIDENCE | 证据链不完整 | 缺少入场核销证据时审核 |
| VERSION_CONFLICT | 单据版本已被他人更新 | 补正时单据版本不匹配 |
| DUPLICATE | 同观众同展会有未归档单据 | 重复提交预约单 |

### 样例数据

系统预置 8 条预约单，包含以下可暴露问题的场景：

1. **重复补录单** — 同观众同展会已存在，再次提交触发 DUPLICATE
2. **缺证据单** — 缺少入场核销和数据回收证据，审核时触发 MISSING_EVIDENCE
3. **覆盖结果单** — 版本冲突测试，用旧版本操作触发 VERSION_CONFLICT
4. **错状态单** — 已归档单据，任何操作触发 WRONG_STATUS
5. **越权测试单** — 用错误角色操作触发 ROLE_MISMATCH
6. **旧版本单** — 被退回的单据，补正时用旧版本触发 VERSION_CONFLICT
7. **待复核单 A** — 已审核通过，复核负责人可归档
8. **待复核单 B** — 已审核通过，复核负责人可归档

## 验证要点

- 登录不同角色，确认只能看到和操作自己权限范围内的功能
- 用错误角色直接调接口（绕过页面），确认后端拦截并返回具体原因
- 审核缺证据的单据，确认页面和接口都提示缺失哪类证据
- 批量操作中混入异常单据，确认逐条返回结果、不影响其他单据
- 补正/审核/归档时用旧版本号，确认版本冲突提示
