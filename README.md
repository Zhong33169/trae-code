# 银行网点-风险分级处置开户申请系统

专为银行网点设计的开户申请风险分级处置系统，严格遵循岗位权限和流程控制，确保每一步操作留痕、风险可控。

## 系统特性

### 🎯 核心业务流程
```
开户预约 → 资料审核 → 账户启用
```

### 👥 岗位权限严格隔离
| 岗位 | 可处理阶段 | 权限说明 |
|------|-----------|----------|
| **客户经理** | 开户预约 | 可推进到资料审核，**不能替运营主管推进** |
| **运营主管** | 资料审核 | 可推进到账户启用，**不能替支行行长归档** |
| **支行行长** | 账户启用 | 完成最终审批归档（签收完成） |

### 📋 状态管理
- **待签收** - 等待当前岗位处理人签收
- **异常回传** - 资料不全或有问题，退回补正
- **签收完成** - 当前阶段处理完成

### ⚠️ 风险分级
- **高风险** - 红色标识，单独识别，需严格审核
- **中风险** - 黄色标识，需加强审核
- **低风险** - 绿色标识，正常流程

### 📝 操作留痕
- 所有状态变更、阶段推进、风险等级调整均记录操作人、时间、原因
- 风险等级降级或升级必须填写原因并留痕
- 版本号控制，防止并发修改冲突
- 操作失败也会记录原因

### 🧪 异常样例覆盖
系统预置9条样例数据，覆盖各种业务场景：
| 场景 | 样例 | 说明 |
|------|------|------|
| ✅ 正常流程 | 张三、赵六、吴九 | 低风险正常流转、已完成归档 |
| ❌ 缺证据 | 王五、郑十 | 缺少必填证据材料 |
| ⏰ 逾期 | 王五、周八 | 超过处理截止日期 |
| 🔙 退回补正 | 王五、周八、郑十 | 不同阶段被退回补充资料 |
| 🔀 状态冲突 | 周八 | 账户启用阶段被退回，需重走流程 |
| 🔴 高风险 | 李四、孙七 | 异地开户、涉监测名单等高风险客户 |
| 📊 风险升级 | 李四、孙七 | 低→中→高，每一步都有留痕 |
| 📉 风险降级 | 冯十一 | 高→中→低，完整降级追溯链路 |
| ❌ 失败操作留痕 | 张三 | 运营主管越权操作被拒，原状态保留 |

## 快速开始

### 0. 环境要求
- Python 3.10+
- Node.js 18+
- npm 或 yarn

### 1. 端口配置

**系统默认端口**（已配置，无需修改即可运行）：
- 后端：`8002`
- 前端：`3002`

**后端端口修改**：编辑 `backend/.env`
```env
PORT=8002
DATABASE_URL=sqlite:///./data/zhong33169.db
```

**前端端口修改**：
1. 编辑 `frontend/.env`
   ```env
   PORT=3002
   NEXT_PUBLIC_API_BASE=http://localhost:8002
   ```
2. 编辑 `frontend/package.json` 中的端口（两处）
   ```json
   "dev": "next dev -p 3002",
   "start": "next start -p 3002"
   ```

> ⚠️ 修改端口后，请确保前端 `NEXT_PUBLIC_API_BASE` 与后端端口一致

---

### 2. 后端启动

```bash
# 进入后端目录
cd backend

# 创建虚拟环境（仅首次）
python3 -m venv .venv

# 激活虚拟环境
source .venv/bin/activate  # macOS/Linux
# 或 Windows: .venv\Scripts\activate

# 安装依赖（仅首次）
pip install -r requirements.txt

# 初始化数据库（幂等迁移，兼容新旧库）
# - 新库：执行建表DDL + 所有迁移 + 插入初始用户
# - 旧库：执行缺失的迁移（如补齐 operation_records.is_success 字段）
python scripts/init_db.py

# 加载样例数据（仅首次，可选）
python scripts/seed_data.py

# 启动后端服务（默认端口 8002）
python run.py
```

> 💡 **数据库迁移说明**：系统使用幂等迁移机制，schema_migrations 表记录已应用的版本。
> V001 迁移负责为旧库补齐 operation_records 表的 is_success 字段，并自动回填值。

**验证后端**：访问 http://localhost:8002/health
```json
{
  "status": "ok",
  "app": "银行网点-风险分级处置开户申请系统"
}
```

## API 接口说明

### 基础路径
`http://localhost:8002/api`

### 主要接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/applications` | 获取开户申请列表（支持筛选） |
| GET | `/applications/:id` | 获取申请详情 |
| POST | `/applications` | 创建新申请 |
| GET | `/applications/:id/operations` | 获取操作记录 |
| GET | `/applications/:id/risk-logs` | 获取风险等级变更日志 |
| POST | `/applications/operation` | 提交操作（核心接口） |
| GET | `/statistics` | 获取统计数据 |
| GET | `/users` | 获取用户列表 |

### 操作提交参数
```json
{
  "operator_id": 1,
  "operator_role": "客户经理",
  "application_id": 1,
  "current_version": 1,
  "action": "advance_stage",
  "remark": "资料齐全，同意推进",
  "evidence_ids_verified": [1, 2, 3],
  "new_risk_level": "medium",
  "risk_change_reason": "客户为异地户籍，需加强审核"
}
```

### 操作类型
- `sign_receive` - 签收处理
- `advance_stage` - 推进到下一阶段
- `sign_complete` - 最终审批完成（仅支行行长）
- `return_back` - 退回补正
- `mark_abnormal` - 标记异常

## 后端校验规则

每次提交操作时，后端会严格校验以下内容，不通过则保留原状态并写操作记录：

1. ✅ **处理人校验** - 校验用户ID是否存在，角色是否匹配
2. ✅ **角色权限校验** - 校验角色是否有权处理当前阶段
3. ✅ **版本校验** - 防止并发修改冲突
4. ✅ **状态校验** - 校验当前状态是否允许该操作
5. ✅ **必填证据校验** - 推进前必须提供所有必填证据
6. ✅ **风险变更校验** - 风险等级调整必须填写原因

## 常见问题

### Q: 前后端端口如何修改？
A: 见上文「端口配置」章节，修改 .env 和 package.json 即可。

### Q: 如何重置数据库？
A: 删除 `backend/data/*.db` 文件，重新运行 `python scripts/init_db.py` 和 `python scripts/seed_data.py`。

### Q: 旧库如何升级到最新表结构？
A: 直接运行 `python scripts/init_db.py`，系统会自动检测缺失的迁移并执行：
   - V001: 为旧库补齐 operation_records 表的 is_success 字段
   - 自动回填历史数据（operation_type='操作失败' 的记录 is_success=0，其余=1）
   - 已应用的迁移不会重复执行

### Q: 迁移脚本如何新增？
A: 在 `backend/app/migrations/` 目录下按 `V<版本号>_<描述>.py` 格式创建文件，
   实现 `def up(cursor)` 函数即可。系统会按版本号顺序自动执行未应用的迁移。

### Q: 如何添加新的样例数据？
A: 编辑 `backend/scripts/seed_data.py` 中的 samples 数组，然后重新运行脚本。

### Q: 操作提交失败怎么办？
A: 查看详情页的「操作记录」标签页，失败的操作也会被记录，包含具体失败原因。

## 注意事项

1. **端口冲突**：确保 3002 和 8002 端口没有被其他程序占用
2. **虚拟环境**：运行后端命令前务必激活虚拟环境
3. **角色模拟**：前端通过切换角色模拟不同岗位人员操作，实际生产环境应对接统一身份认证
4. **数据安全**：本系统为演示用途，生产环境需加强数据加密和安全审计
5. **高风险识别**：高风险申请不仅有颜色标识，还有独立的风险变更日志，满足监管要求
