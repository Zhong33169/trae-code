# 便利店连锁-批量变更复核补货申请系统

基于 Astro + React Islands 前端和 Rust + Rocket + SQLite 后端的补货申请复核管理系统。

## 功能特性

- 三级角色工作流：补货登记员 → 补货审核主管 → 连锁复核负责人
- 补货申请队列视图，支持状态和门店筛选
- 侧边栏实时查看关键证据（门店补货凭证、配送确认单、补货登记凭证）
- 申请详情办理，支持编辑、提交、审核、复核归档等操作
- 批量审核/驳回，逐条返回处理结果（成功、失败、需重试）
- 乐观锁版本控制，防止并发冲突
- 完整的权限校验：错角色、旧版本、缺证据、错状态均被拦截
- 操作历史全记录

## 技术栈

### 前端
- Astro 4.x + React Islands
- React 18
- TypeScript
- 前端默认端口：`4321`（可通过 `FRONTEND_PORT` 环境变量配置）

### 后端
- Rust + Rocket 0.5
- SQLite（rusqlite，bundled 模式）
- 后端默认端口：`8000`（可通过 `BACKEND_PORT` 环境变量配置）

## 初始化

### 后端

```bash
cd backend
cargo build
```

首次运行会自动创建 SQLite 数据库并初始化样例数据。

### 前端

```bash
cd frontend
npm install
```

## 启动

### 方式一：分别启动

启动后端：
```bash
cd backend
cargo run
```

启动前端（另开终端）：
```bash
cd frontend
npm run dev
```

### 方式二：使用环境变量指定端口

```bash
# 后端
BACKEND_PORT=8080 cargo run

# 前端
FRONTEND_PORT=3000 BACKEND_PORT=8080 npm run dev
```

访问 `http://localhost:4321`（或你配置的前端端口）。

## 后端校验规则

后端会对以下情况进行拦截并返回具体原因：

| 拦截类型 | 说明 |
|---------|------|
| 错角色 | 非对应岗位角色执行操作（如审核主管创建申请） |
| 旧版本 | 提交/审核时版本号与当前不一致，需刷新重试 |
| 缺证据 | 提交审核时缺少必要的三种凭证 |
| 错状态 | 在不允许的状态下执行操作（如已归档的申请被重新审核） |

## API 接口

所有接口前缀：`/api`

### 认证
- `POST /auth/login` - 登录

### 门店
- `GET /stores` - 获取门店列表

### 补货申请
- `GET /applications` - 获取申请列表（支持 status、store_id 筛选）
- `GET /applications/:id` - 获取申请详情
- `POST /applications` - 创建申请（登记员）
- `PUT /applications/:id` - 更新申请（登记员，草稿/需补正状态）
- `POST /applications/:id/submit` - 提交审核（登记员）
- `POST /applications/:id/review` - 审核（审核主管）
- `POST /applications/:id/final-review` - 复核归档（复核负责人）
- `POST /applications/batch-review` - 批量审核/复核
- `GET /applications/:id/history` - 获取版本历史
