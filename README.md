# 维修服务平台 - 跨班组交接确认维修报价单系统

> 按真实维修服务处理习惯设计，涵盖报价登记、客户确认/支付、维修调度、跨班组交接、归档全流程。以后端状态为准，权限边界清晰，列表/详情/统计/操作记录数据一致性保证。

## 功能要点

### ✅ 跨班组交接确认场景
- **交接不只是备注**：每一笔交接都独立记录交出人、接收人、双方角色、双方班次、交接备注、确认时间、确认状态
- **确认后同步生效**：接收方点击确认后，报价单的「当前处理人」「所属班次」在列表、详情、统计中同步更新
- **待办提醒**：顶部导航栏、报价单详情页会高亮显示"待我确认的交接"

### 🛡️ 权限边界（后端严格校验）
| 操作 | 客服专员 | 调度专员 | 维修师傅 | 服务经理 |
|---|---|---|---|---|
| 登记/编辑维修报价单 | ✔ | ✘ | ✘ | ✔ |
| 提交待报价 | ✔ | ✘ | ✘ | ✔ |
| 填写报价金额/明细 | ✘ | ✔ **(不能替客服确认客户)** | ✘ | ✔ |
| 客户确认报价/登记支付 | ✔ | ✘ | ✘ | ✔ |
| 分配维修师傅/推进调度 | ✘ **(客服不能替师傅调度推进)** | ✔ | ✘ | ✔ |
| 开始维修/现场操作 | ✘ | ✔ | ✔ | ✔ |
| 退回处理 | ✘ | ✔ | ✔ | ✔ |
| **归档完成** | ✘ | ✘ **(调度不能替经理归档)** | ✘ | ✔ 仅经理可归档 |
| 取消报价单 | ✘ | ✘ | ✘ | ✔ |
| 发起/确认交接 | 同处理人 | 同处理人 | 同处理人 | 全局权限 |

> 越权操作会返回明确错误信息，如：`权限不足: 仅服务经理可归档完成 (师傅调度不能替服务经理归档)`

### 🔄 三大核心互相关联状态
1. **报价单状态**（9态）：草稿 → 待报价 → 已报价待确认 → 客户已确认 → 客户已支付 → 维修中 → 已完成归档 / 已退回 / 已取消
2. **支付状态**：未支付 → 已支付（与客户已确认/客户已支付状态联动）
3. **当前处理人/班次**：随分配、交接操作实时变化（与列表展示、我的待办、交接记录联动）

### 💾 数据一致性
- 所有操作通过后端事务写入同一 SQLite 数据库
- 列表计数、详情状态、统计数据、操作记录、交接记录都是同一份数据库查询
- 前端刷新/重新进入页面，数量与状态完全一致，不会出现"前端变了后端没变"

## 快速启动

### 1. 启动后端

```bash
cd backend

# 安装依赖
go mod tidy

# 初始化 SQLite 并启动（首次运行自动建库、建表、灌入演示数据）
go run main.go
```

启动后会输出：
```
SQLite 数据库连接成功
数据库表初始化完成
种子数据初始化成功
==== 维修服务平台后端启动 ====
端口: 8003
访问地址: http://localhost:8003
```

数据库文件位置：`backend/data/repair.db`（首次启动自动生成）

**重置演示数据**：删除 `backend/data/repair.db` 后重新运行后端即可。

### 2. 启动前端

```bash
cd frontend

# 安装依赖（首次）
npm install
# 或 pnpm install / yarn

# 启动开发服务器
npm run dev
```

启动后访问：**http://localhost:3003**

## 核心接口

所有接口前缀 `/api`，需要登录后在 Header 携带 `Authorization: Bearer <token>`

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/login` | 登录，返回 token |
| GET | `/me` | 获取当前登录用户信息 |
| GET | `/users` | 用户列表（可按角色/班次过滤） |
| GET | `/quotes` | 报价单列表，支持 status/shift/keyword/my_only/page |
| GET | `/quotes/:id` | 报价单详情（含操作记录、交接记录、待我确认的交接） |
| POST | `/quotes` | 登记报价单 |
| POST | `/quotes/:id/submit-quote` | 提交待报价 |
| POST | `/quotes/:id/fill-quote` | 调度填写报价 |
| POST | `/quotes/:id/confirm` | 客服确认客户接受报价 |
| POST | `/quotes/:id/payment` | 客服登记客户支付 |
| POST | `/quotes/:id/assign-tech` | 调度分配维修师傅 |
| POST | `/quotes/:id/start-repair` | 开始维修 |
| POST | `/quotes/:id/return` | 退回处理 |
| POST | `/quotes/:id/complete` | **服务经理归档**（权限最高） |
| POST | `/quotes/:id/cancel` | **服务经理取消**（权限最高） |
| POST | `/quotes/:id/add-evidence` | 补充证据/备注（不改变状态但写入日志） |
| POST | `/quotes/:id/handovers` | 发起换班交接 |
| POST | `/handovers/:id/confirm` | 接收方确认/拒绝交接 |
| GET | `/handovers/mine` | 与我相关的交接记录 |
| GET | `/statistics` | 综合统计（与列表同源） |

所有失败都会返回明确中文错误：如 `无法填写报价: 当前状态为「客户已确认」，仅「待报价」状态可填写`

## 项目结构

```
├── backend/
│   ├── main.go                    # 入口：初始化 DB + Echo 路由
│   ├── go.mod
│   ├── models/models.go           # 数据模型、状态枚举、显示名称映射
│   ├── database/db.go             # SQLite 连接、建表
│   ├── data/seed.go               # 演示种子数据（12张报价单 + 多种状态）
│   ├── middleware/auth.go         # JWT 认证 + 角色权限中间件
│   ├── handlers/auth.go           # 登录/用户接口
│   ├── handlers/quotes.go         # 报价单 CRUD + 状态流转 + 后端校验
│   ├── handlers/handovers.go      # 跨班组交接发起/确认
│   ├── handlers/stats.go          # 统计分析（与列表同源查询）
│   └── data/repair.db             # 首次启动自动生成 SQLite 文件
│
└── frontend/
    ├── next.config.js             # 端口 3003 + /api 代理到 8003
    ├── tailwind.config.ts
    ├── app/
    │   ├── layout.tsx             # 全局布局
    │   ├── globals.css            # 全局样式
    │   ├── page.tsx               # 根路径自动跳 /quotes
    │   ├── login/page.tsx         # 登录页（含快速角色切换）
    │   └── (app)/
    │       ├── layout.tsx         # 主框架：左侧菜单 + 用户栏 + 交接待办红点
    │       ├── quotes/page.tsx    # 列表（8个状态统计卡+筛选+分页）
    │       ├── quotes/[id]/page.tsx # 详情（核心页，左右两栏，右侧操作面板）
    │       ├── handovers/page.tsx # 换班交接中心
    │       └── statistics/page.tsx # 统计分析
    ├── lib/api.ts                 # fetch 封装、Token管理、格式化工具
    └── types/index.ts             # 类型定义 + 状态/角色配色
```
