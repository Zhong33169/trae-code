# 法务服务中心 · 诉讼材料登记与复核管理系统

## 技术栈

| 层级 | 技术 | 端口 |
|------|------|------|
| 前端 | Vue 3 + Vite + Element Plus + Pinia + Vue Router | **3004** |
| 后端 | Rust + Rocket + SQLite (rusqlite) | **8004** |
| 跨域 | 后端 CORS 放行 `http://127.0.0.1:3004`；前端通过 `/api` 代理到后端 | — |

## 启动方式

### 1. 后端（Rust + Rocket，端口 8004）

```bash
cd backend
# Rust 工具链需要 1.75+，首次编译较慢（会拉取并编译 Rocket、rusqlite-bundled-SQLite 等）
cargo run
# 启动后自动：
#   · 在 backend/data/litigation.db 创建 SQLite 数据库
#   · 自动灌入演示用户、8 份材料单、20+ 附件、状态流转日志、审计记录
# 验证：访问 http://127.0.0.1:8004/api/materials/stats/summary 应返回 JSON
```

### 2. 前端（Vue 3 + Vite，端口 3004）

```bash
cd frontend
npm install   # 首次安装
npm run dev   # 启动：http://127.0.0.1:3004
```

## 页面组织

系统页面严格围绕诉讼材料单的三个阶段组织：

1. **诉讼材料登记（登记员）**：新建登记 → 填入案件 + 截止 + 附件 → 发起
2. **过程核验（审核主管 + 复核负责人）**：领取审核 → 核验附件 → 退回/通过 → 领取复核 → 通过并归档
3. **复核归档（复核负责人）**：复核通过 → 待归档 → 一键归档

### 主要页面

| 路径 | 页面 | 说明 |
|------|------|------|
| `#/dashboard`       | 工作台     | 概览统计（总数、超时、附件异常） + 我的待办 + 最近异常审计 |
| `#/materials`       | 材料单列表 | 按状态/优先级/类型/超时/附件异常筛选 + 批量处理 + 逐条结果说明 |
| `#/materials/new`   | 新建登记   | 登记员填写案件信息 + 附件清单后发起 |
| `#/materials/:id`   | 详情页     | 案件信息 / 附件管理（可驳回并写原因、恢复有效） / 处理步骤流 / 流转历史 |
| `#/audit`           | 审计日志   | 所有操作进审计；失败原因、操作人、操作时间、关联材料/附件可查 |
| `#/batches`         | 批量任务   | 每次批量处理的总数/成功/失败/跳过 + 逐条明细 |

## 演示数据与验收样例

首次启动后端时 `backend/src/db/init.rs` 会自动初始化 **8 份诉讼材料单**，覆盖所有验收场景：

### ✅ 正常单（CASE-2026-0001 买卖合同纠纷一审）
- 状态：`registered`（待审核）
- 说明：原告、被告、管辖、截止日期齐全，4 个附件（3 个必填全部有效），无任何驳回
- **验收建议**：
  1. 用 `reviewer1`（王审核）登录 → 列表页找到 → 点"领取审核" → 再点"审核通过"
  2. 切换到 `verifier1`（陈复核）→ 看到该单变为 `review_passed` → 领取复核 → 通过并归档
  3. 在审计日志筛选操作人、成功，可看到完整登记 → 审核 → 复核 → 归档链路

### ⚠️ 缺材料单（CASE-2026-0003 劳动合同争议仲裁执行）
- 状态：`reviewing`（审核中，已被王审核领取）
- 说明：必填附件「工资银行流水.pdf」**已被赵主管驳回**，原因："银行流水缺少离职前3个月完整记录，仅有复印件无银行盖章"
- **验收建议**：
  1. 在详情页查看「诉讼材料附件管理」，可看到该附件标红，显示 **驳回原因、驳回人、驳回时间**（被驳回的附件保留原因不删除）
  2. 用 `registrar1` / `registrar2` 任意登记员角色 → 在详情页点"添加附件"，上传一个新的必填附件「银行流水（盖章版）.pdf」
  3. 点「重新提交」按钮，若必填附件仍异常会被拦截提示；补齐后才能回到审核队列

### ⏰ 超时单（CASE-2026-0002 借款合同纠纷再审）
- 状态：`registered`（待审核），`截止日 2026-06-19`（在当前日期 2026-06-18 之后仍为待处理状态，系统自动标注为「超时」）
- 说明：登记后未领取、未处理，已超期约 48 小时
- **验收建议**：
  1. 列表页顶部勾选「只看超时」可直接筛出
  2. 每行显示「超期 N 小时」标签；工作台红色统计显示「超期未处理」
  3. 登记时即写入审计 `result=fail`、原因"材料已超期未审核"，可在审计日志直接搜索"超期"
  4. 审核主管领取后，需确认「审计/备注」，该备注会永久保留在材料单详情顶部

### ↩️ 退回单（CASE-2026-0004 建设工程施工合同纠纷）
- 状态：`returned`（已退回补正）
- 说明：赵主管审核后退回，**原因**："缺少竣工验收报告原件及工程结算对账单，见附件驳回原因"；且「竣工验收报告.pdf」被单独驳回，原因："仅提交复印件，无三方盖章原件"
- **验收建议**：
  1. 用 `registrar1`（登记员）登录 → 进入详情 → 顶部红色警告直接显示退回原因
  2. 详情页「添加附件」→ 新增必填「工程结算对账单原件.pdf」
  3. 附件列表中「竣工验收报告.pdf」是被驳回状态——**登记员不能删除驳回附件，只能新增替代**，被驳回附件永久保留驳回原因；如需恢复只能由审核主管操作
  4. 附件全部齐全后点击「补齐附件后重新提交」，状态由 `returned` 变为 `registered`（回到处理队列）
  5. 在审计日志筛选「结果=失败」，能看到赵主管的退回记录和驳回附件记录，包含**谁、什么时候、为什么**

### 📚 其他参照单
- `CASE-2026-0005`：审核通过，等待复核（演示"待复核"状态）
- `CASE-2026-0006`：复核通过，等待归档（演示"待归档"状态 + 顶部审计备注显示）
- `CASE-2026-0007`：已完整归档（演示 4 步流程时间轴、归档人、完整流转日志）
- `CASE-2026-0008`：刚登记（快速体验从 0→归档的完整流程）

## 批量处理 & 逐条说明

列表页支持 3 种批量操作，严格按角色显示按钮（非角色用户按钮禁用）：

| 动作 | 允许角色 | 说明 |
|------|----------|------|
| **批量审核通过** | 诉讼材料审核主管 | 对已登记/退回（但附件齐全）的单据批量通过 |
| **批量复核通过** | 法务服务中心复核负责人 | 对审核通过单据批量复核 |
| **批量归档**     | 法务服务中心复核负责人 | 对已复核单据批量归档 |

### 批量结果逐条说明的样例演示

1. 用 `reviewer1`（审核主管）登录 → 列表页同时勾选：
   - `CASE-2026-0001`（正常单，附件齐全，**应成功**）
   - `CASE-2026-0002`（超时单，但附件齐全，**应成功，带超时提示**）
   - `CASE-2026-0003`（有被驳回的必填附件，**应失败**）
   - `CASE-2026-0004`（已退回+附件不全，**应失败**）
   - `CASE-2026-0006`（已复核，状态不符，**应跳过**）
2. 点「批量审核通过」→ 填批次名「2026年6月第一批」→ 确认
3. 弹出的结果窗口中：
   - **成功 2**：CASE-2026-0001（"附件齐全，审核通过"）、CASE-2026-0002
   - **失败 2**：CASE-2026-0003（"必填附件异常：N 项缺失或被驳回，需补正后才能批量通过"）、CASE-2026-0004
   - **跳过 1**：CASE-2026-0006（"当前状态为 \"待归档\"，不可批量审核通过"）
4. 所有失败均进入 `audit_logs`，带 `batch_id` 关联批次；「批量任务」页面查看完整历史

## 工程约束落实情况

| 需求 | 落实位置 |
|------|----------|
| 前端端口 **3004** | [vite.config.js](file:///Users/kuzhiluoya/Desktop/zqzl/zhong33169/trae-code-4/frontend/vite.config.js) `server.port = 3004` |
| 后端端口 **8004** | [Rocket.toml](file:///Users/kuzhiluoya/Desktop/zqzl/zhong33169/trae-code-4/backend/Rocket.toml) `port = 8004` |
| 请求地址指向后端 | 前端 `/api` 通过 Vite 代理 → `http://127.0.0.1:8004` |
| 后端 CORS 放行前端 | [cors.rs](file:///Users/kuzhiluoya/Desktop/zqzl/zhong33169/trae-code-4/backend/src/cors.rs) 放行 `http://localhost:3004` + `http://127.0.0.1:3004` |
| 数据库 SQLite 演示数据 | [init.rs](file:///Users/kuzhiluoya/Desktop/zqzl/zhong33169/trae-code-4/backend/src/db/init.rs) 首次运行自动建表 + 种子数据；DB 存 `backend/data/litigation.db` |
| 角色切换非仅藏按钮 | 后端每接口都用 `role_can()` 做二次权限判断，前端按钮仅做表现 |
| 附件补齐后才可回队列 | 后端「重新提交」与「领取审核」前都调用 `has_required_attachments()` 校验，缺失直接报错 |
| 被驳回附件保留原因 | 附件「驳回」仅改 `status='rejected'` 并写 `reject_reason/rejected_by/rejected_at`，**不物理删除** |
| 失败原因进审计 | 所有关键失败（退回、驳回附件、批量失败、超期登记）都调用 `insert_audit()` 写入 `audit_logs` 表，字段覆盖：操作人 / 角色 / 时间 / 动作 / 失败原因 / 关联单据和附件 |
| 批量结果逐条说明 | 后端 `batch_process` 对每条材料逐个 `details.push(...)`，前端对话框表格 + 「批量任务」详情页均逐条展示 |
