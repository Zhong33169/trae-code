# 工程监理公司-异常申诉复核旁站记录单系统

基于 **Remix + Koa + SQLite** 构建的工程监理旁站记录全流程管理系统。

## 系统概述

本系统实现工程监理旁站记录从登记、审核到复核归档的完整业务流程，重点关注旁站记录单的连续处理能力，支持多种异常场景处理。

### 核心角色

| 角色 | 用户名 | 密码 | 职责 |
|------|--------|------|------|
| 旁站记录登记员 | registrar1 / registrar2 | 123456 | 发起旁站记录、补正材料、再次提交 |
| 旁站记录审核主管 | supervisor1 / supervisor2 | 123456 | 审核旁站记录、提出补正要求、标记异常 |
| 工程监理公司复核负责人 | reviewer1 / reviewer2 | 123456 | 最终复核、归档、裁定状态冲突 |

### 业务流程

```
旁站记录登记员
      ↓
  起草/创建记录 → 提交审核
      ↓
旁站记录审核主管
      ↓
  ┌─────────────┬───────────────┬──────────────────┬───────────────┐
  ↓             ↓               ↓                  ↓               ↓
审核通过     审核驳回       退回补正         标记缺证据     标记状态冲突
  ↓             ↓               ↓                  ↓               ↓
  │         登记员整改       登记员补正         补充证据       现场核实
  │             └───────────┐    │                  │               │
  │                         ↓    ↓                  ↓               │
  └──────────────→     再次提交   ←─────────────────┴───────────────┘
                              ↓
                     重新进入审核流程
                              ↓
工程监理公司复核负责人
                              ↓
                    ┌─────────────┐
                    ↓             ↓
                复核通过       复核驳回
                    ↓             ↓
                  归档        退回重审
```

### 状态说明

| 状态 | 说明 | 颜色标识 |
|------|------|----------|
| 草稿 | 登记员新建未提交 | ⚪ 默认 |
| 已提交待审核 | 已提交，等待审核主管处理 | 🔵 蓝色 |
| 审核中 | 审核主管正在处理 | 🟡 处理中 |
| 审核通过 | 审核主管审核通过，等待复核 | 🟢 成功 |
| 审核驳回 | 审核主管驳回，需整改后重新提交 | 🔴 错误 |
| 需补正 | 审核主管要求补充材料 | 🟠 警告 |
| 已补正 | 登记员已补正，等待再次审核 | 🔵 蓝色 |
| 复核中 | 复核负责人正在处理 | 🟡 处理中 |
| 复核通过 | 最终复核通过，可归档 | 🟢 成功 |
| 复核驳回 | 最终复核驳回 | 🔴 错误 |
| 缺证据 | 缺少必要的证据材料 | 🟠 警告 |
| 逾期 | 超过处理截止时间 | 🔴 红色 |
| 状态冲突 | 多方反馈状态不一致，需现场核实 | 🟣 洋红 |
| 已归档 | 流程完成，已归档 | ⚪ 默认 |

## 技术栈

### 前端
- **Remix 2** - 全栈 React 框架
- **React 18** - UI 库
- **TypeScript** - 类型安全
- **Ant Design 5** - UI 组件库
- **Vite** - 构建工具

### 后端
- **Koa 2** - Node.js Web 框架
- **@koa/router** - 路由
- **better-sqlite3** - SQLite 数据库驱动
- **jsonwebtoken** - JWT 认证
- **bcryptjs** - 密码加密
- **dayjs** - 日期处理

### 数据库
- **SQLite 3** - 本地文件数据库，无需额外安装

## 端口配置

系统默认端口：
- **前端**: 3004
- **后端**: 8004

### 修改端口

如需修改端口，可通过环境变量配置：

#### 后端端口修改
```bash
# 修改 backend/.env
PORT=8004  # 改为需要的端口

# 同时需要修改前端 vite.config.ts 中的代理配置
# 修改 frontend/vite.config.ts
const DEFAULT_BACKEND_PORT = process.env.BACKEND_PORT || '8004';
```

#### 前端端口修改
```bash
# 修改 frontend/.env
FRONTEND_PORT=3004  # 改为需要的端口
BACKEND_PORT=8004   # 需与后端端口保持一致

# 修改 frontend/vite.config.ts
const DEFAULT_FRONTEND_PORT = process.env.FRONTEND_PORT || '3004';
```

## 快速开始

### 前置要求
- Node.js >= 18.0.0
- npm 或 yarn

### 1. 安装依赖

```bash
# 安装后端依赖
cd backend
npm install

# 安装前端依赖
cd ../frontend
npm install
```

### 2. 初始化数据库

```bash
cd backend

# 初始化数据库表结构
npm run init-db

# 插入样例数据（包含多种状态场景）
npm run seed-data
```

数据库文件将创建在 `backend/data/supervision.db`

### 3. 启动服务

```bash
# 启动后端服务（默认端口 8004）
cd backend
npm start
# 或开发模式
npm run dev

# 启动前端服务（默认端口 3004）
cd frontend
npm run dev
```

### 4. 访问系统

打开浏览器访问：http://localhost:3004

使用测试账号登录，查看不同角色的操作界面。

## 核心功能演示流程

### 流程演示：申诉提交 → 驳回 → 补正 → 再次提交 → 复核通过

以 **PZ-2024-003**（需补正）为例：

1. **登录登记员账号** (registrar1 / 123456)
   - 查看工作台，看到"需补正"待办事项
   - 进入记录详情，查看上一处理人（审核主管）的意见和驳回原因
   - 点击"补正材料"，填写补正说明，补充证据

2. **补正提交后**
   - 状态变为"已补正"
   - 自动流转回审核主管处理

3. **切换到审核主管账号** (supervisor2 / 123456)
   - 在待办中看到已补正的记录
   - 查看补正后的内容和补充的证据
   - 审核通过，提交到监理公司复核

4. **切换到复核负责人账号** (reviewer1 / 123456)
   - 开始复核，查看完整的审核历史和所有意见
   - 复核通过，完成归档

### 异常场景演示

1. **缺证据场景** (PZ-2024-004)
   - 审核主管标记"缺证据"，填写具体缺失的证据类型
   - 登记员补充证据后重新提交
   - 后端校验必须包含照片证据

2. **状态冲突场景** (PZ-2024-009)
   - 审核主管标记"状态冲突"，说明冲突原因
   - 登记员现场核实后补正说明
   - 复核负责人可最终裁定

3. **版本冲突校验**
   - 当两人同时操作同一条记录时
   - 后端校验版本号，先提交的成功，后提交的提示版本冲突
   - 保留原状态，记录操作日志

## 后端校验机制

每次提交操作时，后端会严格校验以下内容：

### 1. 处理人校验
- 验证当前用户是否为记录的指定处理人
- 非处理人操作将被拒绝并记录日志

### 2. 角色权限校验
- 基于角色的访问控制 (RBAC)
- 每种操作只能由指定角色执行
- 例如：审核操作只能由审核主管执行

### 3. 状态流转校验
- 严格的状态机控制
- 每种状态下只允许特定的操作
- 例如：已归档的记录不能再进行任何修改

### 4. 版本号校验
- 每条记录带有版本号（version）
- 提交时必须匹配当前版本
- 防止并发修改导致的数据不一致

### 5. 必选证据校验
- 提交审核前必须包含至少1份照片证据
- 缺证据状态下补正时必须补充缺失的证据类型

### 6. 校验失败处理
- 校验不通过时，**保留原状态**不改变
- 写入操作日志，记录失败原因
- 返回明确的错误信息给前端

## API 接口

### 认证接口
- `POST /api/auth/login` - 登录
- `POST /api/auth/logout` - 退出
- `GET /api/auth/profile` - 获取当前用户信息

### 旁站记录单接口
- `GET /api/records` - 获取记录列表（支持分页、筛选）
- `GET /api/records/:id` - 获取记录详情
- `POST /api/records` - 创建记录
- `PUT /api/records/:id` - 更新记录
- `DELETE /api/records/:id` - 删除记录（仅草稿）
- `POST /api/records/:id/operate` - 执行操作（提交/审核/复核/补正等）
- `GET /api/records/statistics` - 获取统计数据
- `GET /api/records/options` - 获取下拉选项

### 操作日志接口
- `GET /api/logs` - 获取操作日志列表

## 常见问题

### 1. 端口被占用
修改 `.env` 文件中的端口配置，确保前后端端口一致。

### 2. better-sqlite3 安装失败
better-sqlite3 需要编译原生模块，请确保系统已安装 Python 和 C++ 编译工具：
- Windows: `npm install --global windows-build-tools`
- macOS: `xcode-select --install`
- Linux: `sudo apt-get install build-essential python3`

### 3. 前端无法连接后端
- 确认后端服务已启动
- 检查端口配置是否一致
- 查看 vite.config.ts 中的代理配置
