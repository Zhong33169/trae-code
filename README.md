# 水务营业厅跨班组交接确认开户申请系统

## 项目概述

本系统用于水务营业厅的开户申请跨班组交接确认管理，实现开户申请全流程状态追踪、班组交接记录、岗位权限控制和操作一致性保障。

## 技术栈

- **前端**: Lit 3.0 + Vite 5 (端口 3002)
- **后端**: Go 1.21 + Chi v5 (端口 8002)
- **数据库**: SQLite 3 (本地文件存储)

## 岗位角色说明

| 岗位 | 职责 | 权限范围 |
|------|------|----------|
| 开户登记员 | 开户申请发起/补正 | 录入资料、补正资料、发起交接、查看申请 |
| 开户审核主管 | 审核办理 | 审核资料、退回/通过申请、接收交接、办理申请 |
| 水务营业厅复核负责人 | 复核归档 | 最终复核、归档、统计查看、跨班组管理 |

## 快速启动

### 1. 数据库初始化

系统首次启动时会自动创建 `water_office.db` 数据库文件，并初始化表结构和样例数据，无需手动建库。

### 2. 后端启动

```bash
cd backend
go mod tidy
go run main.go
# 服务启动于 http://localhost:8002
```

后端启动参数说明：
- `-port=8002`: 服务端口
- `-db=./water_office.db`: 数据库文件路径

### 3. 前端启动

```bash
cd frontend
npm install
npm run dev
# 服务启动于 http://localhost:3002
```

## 系统功能入口

### 页面入口
- 登录页: `http://localhost:3002/`
- 申请列表: `http://localhost:3002/#/applications` (登录后默认首页)
- 新建申请: `http://localhost:3002/#/applications/new` (开户登记员)
- 申请详情: `http://localhost:3002/#/applications/:id`
- 交接管理: `http://localhost:3002/#/handovers`
- 统计看板: `http://localhost:3002/#/statistics`

### 开户申请状态流转

```
DRAFT(草稿) 
  → 登记员提交 → PENDING_AUDIT(待审核)
     → 审核通过 → PENDING_REVIEW(待复核)
        → 复核通过 → ARCHIVED(已归档) ✅
     → 审核退回 → NEED_CORRECTION(需补正)
        → 登记员补正后 → PENDING_AUDIT(待审核)
        → 登记员撤回 → DRAFT(草稿)
     → 复核退回 → PENDING_AUDIT(待审核)
```

### 跨班组交接流程
1. 交出人在申请详情页点击「发起交接」
2. 选择接收人和班次，填写交接说明
3. 接收人在「交接管理」页面确认接收
4. 系统记录完整交接链：交出人→接收人→班次→时间→说明

## API 接口规范

所有接口统一响应格式：
```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```
- `code=0` 表示成功，非 0 表示业务错误
- `message` 返回具体错误原因，不使用通用提示

### 错误码说明
| 错误码 | 说明 |
|--------|------|
| 1001 | 未登录或登录已过期 |
| 1002 | 权限不足，当前岗位无法执行此操作 |
| 2001 | 申请状态不允许此操作 |
| 2002 | 资料不完整，缺少必填字段 |
| 2003 | 申请不存在或已被删除 |
| 3001 | 交接状态错误 |
| 3002 | 不能交接给自己 |
| 3003 | 接收人岗位不匹配 |

### 一致性保证
- 所有状态变更均由后端数据库事务完成
- 列表/详情/统计均查询同一数据源，不做前端独立计算
- 每次操作写入 `operation_logs` 表，可追踪
- 页面加载时重新拉取数据，刷新后数据完全一致
