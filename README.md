# B2B批发平台 - 商家入驻单系统

离线台账回填商家入驻单系统，支持商家入驻、资质审核、店铺开通全流程管理。

## 技术架构

- **前端**: Next.js 14 (App Router) + React 18 + TypeScript
- **后端**: Node.js + Fastify + TypeScript
- **数据库**: SQLite (better-sqlite3)
- **端口**:
  - 前端: `3107`
  - 后端: `8107`

## 快速开始

### 1. 安装依赖

```bash
# 安装后端依赖
cd backend
npm install

# 安装前端依赖
cd ../frontend
npm install
```

### 2. 初始化数据库并导入测试数据

```bash
cd backend
npm run seed
```

> **注意**: 种子数据脚本会自动创建数据库表并插入测试样例。

### 3. 启动后端服务

```bash
cd backend
npm run build
npm start
# 或开发模式: npm run dev
```

后端服务将运行在 `http://localhost:8107`

### 4. 启动前端服务

```bash
cd frontend
npm run dev
# 或生产模式: npm run build && npm start
```

前端服务将运行在 `http://localhost:3107`

## 核心功能

### 1. 三页签业务组织
系统按业务流程分为三个页签，各页签独立展示对应队列和可办操作：
- **商家入驻**: 入驻登记、材料补正、退回重提（登记员视角）
- **资质审核**: 受理审核、材料核查、资质判定（审核主管视角）
- **店铺开通**: 资质复核、店铺开通、档案归档（复核负责人视角）

每个页签支持：
- 统计卡片：待我处理、已超时、异常单、本页签总计
- 视图切换：待办队列（仅当前角色待办+异常）/ 全部单据
- 批量操作：按页签分离，异常单不可勾选

### 2. 待处理队列
- 按角色自动过滤当前用户可处理的单据
- 支持按状态、异常、超时条件筛选
- 支持关键词搜索（商家名称、批次号、联系人、电话）
- 异常单红色高亮，超时单橙色高亮
- 支持批量选择和批量处理
- 列表排序：异常优先 → 超时优先 → 创建时间降序

### 3. 详情处理
- 展示完整的商家信息和资质信息
- 附件管理（上传、删除）
- 退回原因、补正说明、审计备注展示
- 处理时间线（创建、提交、审核、归档时间）
- 操作按钮根据角色和状态动态显示
- 异常时显示明确的错误信息并禁止操作

### 4. 异常闭环处理

#### 异常类型
- **重复批次**: 批次号与其他入驻单重复
- **状态不一致**: 线上状态与离线台账状态不一致

#### 异常检测
- 创建入驻单时自动检测批次号是否重复
- 对比线上状态与离线台账状态
- 检测结果写入审计日志（`DETECT_EXCEPTION` 操作类型）

#### 异常单规则
- 异常单 **禁止流转操作**（提交、审核、开通店铺等）
- 异常单 **允许登记审计备注**（所有角色均可）
- 尝试流转操作会被拦截并记录审计日志

#### 离线台账状态更正
- 所有角色均可更正离线台账状态
- 更正后系统自动重新校验异常
- 若异常已消除，自动清除异常标记
- 若异常仍存在，保留异常标记

#### 异常解除
- 仅 **审核主管 (SUPERVISOR)** 可解除异常标记
- 解除时必须填写解除原因
- 解除原因永久保存到审计日志
- 解除后恢复正常流转

### 5. 审计日志
- 所有操作均记录审计日志（谁、什么时候、做了什么、为什么）
- 包含：操作人、角色、操作类型、状态变更、原因、备注
- 支持按操作人、操作类型、日期范围筛选
- **异常检测持久化**: 重复批次、状态不一致原因写入审计
- **批量失败持久化**: 批量处理失败原因逐条写入审计
- **操作拦截持久化**: 异常单尝试流转被拦截也记录审计

### 6. 角色权限

| 操作 | 登记员 (CLERK) | 审核主管 (SUPERVISOR) | 复核负责人 (REVIEWER) |
|------|---------------|---------------------|---------------------|
| 创建入驻单 | ✅ | ❌ | ❌ |
| 提交审核 | ✅ | ❌ | ❌ |
| 开始审核 | ❌ | ✅ | ❌ |
| 退回补正 | ❌ | ✅ | ❌ |
| 资质通过 | ❌ | ✅ | ❌ |
| 驳回 | ❌ | ✅ | ❌ |
| 补正重提 | ✅ | ❌ | ❌ |
| 开通店铺 | ❌ | ❌ | ✅ |
| 归档 | ❌ | ❌ | ✅ |
| 上传/删除附件 | ✅（仅草稿） | ❌ | ❌ |
| 添加审计备注 | ✅ | ✅ | ✅ |
| 更正离线台账 | ✅ | ✅ | ✅ |
| 解除异常标记 | ❌ | ✅ | ❌ |

> **异常单特殊规则**: 异常单禁止所有流转操作，仅允许：添加审计备注、更正离线台账、解除异常（仅主管）

### 7. 批量处理
- 支持批量选择单据进行同一操作
- 批量操作按页签分离（不同页签有不同批量操作）
- 批量结果逐条说明成功/失败原因
- 自动跳过异常单和权限不足的单据
- 所有失败场景均写入 `BATCH_FAILED` 审计日志

### 8. 角色切换
- 顶部导航栏实时显示当前用户和角色
- 下拉选择可快速切换角色
- 切换后自动刷新列表，只显示当前角色可处理的单据
- 非当前角色处理的单据只能查看，不能操作（仅可加审计备注）

### 9. 状态流转

```
草稿 → 已提交待审核 → 审核中 → 资质审核通过 → 店铺已开通 → 已归档
                ↓         ↓
            待补正材料   已驳回
                ↓         ↓
                └────→ 审核中（补正重提后）
```

| 状态 | 处理角色 | 可执行操作 | 下一状态 |
|------|----------|------------|----------|
| 草稿 | 登记员 | 提交审核 | 已提交待审核 |
| 已提交待审核 | 审核主管 | 开始审核 | 审核中 |
| 审核中 | 审核主管 | 退回补正 / 通过资质 / 驳回 | 待补正材料 / 资质审核通过 / 已驳回 |
| 待补正材料 | 登记员 | 补正后重提 | 审核中 |
| 已驳回 | 登记员 | 补正后重提 | 审核中 |
| 资质审核通过 | 复核负责人 | 开通店铺 | 店铺已开通 |
| 店铺已开通 | 复核负责人 | 复核归档 | 已归档 |
| 已归档 | - | - | - |

> **异常中断**: 单据一旦标记异常，所有流转操作被冻结，需先解除异常才能继续。

## API 接口

所有接口前缀: `/api`

### 用户相关
- `GET /users` - 获取所有用户
- `GET /users/current` - 获取当前用户
- `POST /users/switch` - 切换用户

### 入驻单相关
- `GET /forms` - 获取入驻单列表（队列）
- `GET /forms/:id` - 获取入驻单详情
- `POST /forms` - 创建入驻单
- `POST /forms/:id/action` - 执行操作
- `GET /forms/:id/validate` - 校验入驻单

### 附件相关
- `POST /forms/:id/attachments` - 上传附件
- `DELETE /forms/:id/attachments/:attachmentId` - 删除附件

### 审计日志
- `GET /audit-logs` - 查询审计日志

### 批量处理
- `POST /batch/process` - 批量处理入驻单

### 其他
- `GET /meta` - 获取元数据（角色、状态、操作枚举）
- `GET /health` - 健康检查

### 用例11: 混合场景总览验证
1. 依次切换三个角色，确认每个页签的统计卡片数量正确
2. 商家入驻页签：草稿 + 缺材料 + 退回 + 异常草稿
3. 资质审核页签：已提交 + 审核中 + 超时 + 状态不一致异常
4. 店铺开通页签：资质通过 + 店铺开通 + 已归档 + 重复批次异常
5. 所有页签的异常单均显示在列表顶部，红色高亮

## CORS 配置

后端已配置 CORS，仅允许前端 `http://localhost:3107` 访问：

```typescript
server.register(cors, {
  origin: 'http://localhost:3107',
  credentials: true,
});
```

前端通过 Next.js rewrites 代理 API 请求：

```javascript
// next.config.js
async rewrites() {
  return [
    {
      source: '/api/:path*',
      destination: 'http://localhost:8107/api/:path*',
    },
  ];
}
```

## 常见问题

### Q: 数据库文件在哪里？
A: `backend/data/merchant-onboarding.db`

### Q: 如何重置数据库？
A: 删除 `backend/data/` 目录，然后重新运行 `npm run seed`

### Q: 端口被占用怎么办？
A: 修改 `backend/src/main.ts` 中的 `PORT` 常量，以及 `frontend/next.config.js` 中的 rewrites 配置

### Q: 如何添加新的测试数据？
A: 编辑 `backend/src/seed.ts`，然后重新运行 `npm run seed`
