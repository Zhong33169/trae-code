# 直播电商团队 - 附件缺失补正直播选品单系统

基于 **Go + Echo（后端 8009）** 与 **Fresh/Deno（前端 3009）** + **SQLite** 的直播选品单附件缺失补正流程管理系统。

---

## ✨ 快速启动

### 1. 启动后端（端口 8009）

```bash
cd backend
go run ./cmd/server
# 或先编译再执行：go build -o bin/server ./cmd/server && ./bin/server
```

- 数据库文件会自动创建在 `backend/data/live_selection.db`（首次启动自动 seed 样例数据）。
- 健康检查：<http://localhost:8009/api/health>

### 2. 启动前端（端口 3009）

```bash
cd frontend
deno task start
```

打开 <http://localhost:3009> 即可使用。

> 前端已在 API 层直连 `http://localhost:8009/api`，后端 CORS 已放行 `localhost:3009`。

## 👥 角色说明（不能只在前端藏按钮，后端按角色鉴权）

| 角色 | 用户（seed 内置） | 职责 |
|------|------|------|
| **直播选品登记员（registrar）** | `u_registrar_1` / 直播选品登记员-小李 | 新建选品单、上传附件、提交审核、缺材料时补正附件后重新提交 |
| **直播选品审核主管（supervisor）** | `u_supervisor_1` / 直播选品审核主管-王主管 | 审核办理：通过、标记缺材料（驳回附件保留原因）、退回、记录处理结果 |
| **复核负责人（reviewer）** | `u_reviewer_1` / 复核负责人-张总 | 复核：通过后归档，或复核退回，处理超时单 |

所有接口均在后端通过 `RequireRole` 中间件做权限校验，前端按钮仅做展示便利，直接调用 API 同样会被鉴权。

## 📋 页面组织

- **选品单登记**：登记员可新建、上传附件、提交审核
- **过程核验**：审核主管按附件/材料完整性审核，驳回附件会保留原因
- **复核归档**：复核负责人对通过的选品单进行归档或退回，超时单也可归档

列表支持：
- 按状态筛选（草稿/待审核/缺材料/已退回/已通过/已归档/超时/仅异常）
- 关键字搜索（编号/商品名/品牌）
- 按角色视角展示（登记员只看自己的，审核主管看待处理+已处理，复核负责人看可归档的）

详情页四个 Tab：
1. **📋 基本信息**：商品、价格、佣金、时间等
2. **📎 附件**：附件列表，有效/已驳回区分显示，驳回附件保留驳回原因、驳回人、时间
3. **✅ 处理结果 / 退回原因**：结果、退回原因、审计备注
4. **📜 审计日志**：谁、什么时候、做了什么、详情（包含失败原因）

## 🔄 状态流转

```
draft(草稿) ──提交──▶ pending(待审核)
                         │
              ┌──────────┼───────────┐
              ▼          ▼           ▼
      missing_attachment  approved  rejected(退回)
      (缺材料,驳回附件    (通过)      (退回登记员)
        保留原因)           │
              │             ▼
              │          archived(归档) 或 reviewer 退回复选
              │             ▲
              └──补正附件后──┘ (补齐≥2份有效附件才能回到处理队列)
                         │
                         ▼
                      timeout(超时) ──▶ archived(归档)
```

## 🧪 验收样例（seed 已内置，启动即可看到）

所有样例可在首页列表直接查看，状态筛选可快速定位。

### 🟢 正常单：sel_normal（高端护肤精华液）
- 状态：`pending` 待审核
- 路径：详情页切换到「审核主管」→ 审核通过 → 切「复核负责人」→ 归档
- 包含：2 份有效附件（品牌授权书、质检报告）

### 🟡 缺材料单：sel_missing（网红零食大礼包）
- 状态：`missing_attachment` 缺材料待补正
- 路径：切「登记员」→ 详情 → 上传至少 1 份新附件（总共 ≥2 份有效） → 提交审核 → 切「主管」审核
- 触发校验：未补齐附件时点"提交审核"会被后端拒绝，提示"至少需要 2 份有效附件"
- 包含：目前仅 1 份有效附件（图片资料）

### 🟣 超时单：sel_timeout（夏季防晒衣）
- 状态：`timeout` 超时
- 路径：切「复核负责人」→ 详情 → 归档结案
- 包含：审计日志中可追溯超时未处理的结果

### 🔴 退回单：sel_rejected（杂牌蓝牙耳机）
- 状态：`rejected` 已退回
- 关键：2 份附件均被驳回（分别有驳回原因），退回原因写明「品牌授权存疑，质检报告不完整」
- 路径：切「登记员」→ 详情 → 重新上传有效附件 → 提交审核（需 ≥2 份有效）
- 审计日志可查看：谁、什么时候、为什么没处理成功

### 已通过单：sel_approved（家用空气炸锅）
- 状态：`approved` 审核通过，等待复核归档
- 可测试：复核负责人"复核退回"功能（需填原因，原因会进入审计）

### 草稿单：sel_draft（儿童益智玩具套装）
- 状态：`draft` 草稿，可继续编辑、上传附件后提交

## 📦 批量操作

- **审核主管**：列表可多选 → 批量通过 / 批量退回（逐条说明处理结果）
- **复核负责人**：列表可多选 → 批量归档（逐条说明成功/失败原因）
- 批量结果会在页面顶部弹出，逐条列明 `商品：✅成功/❌失败原因`

---

## 📜 审计追踪

所有状态变更、附件操作、结果记录都会写入 `audit_logs` 表，详情页"审计日志"Tab 可查。字段包括：
- 操作人（ID + 姓名）
- 时间
- 操作类型（创建、提交、驳回附件、退回、审核通过、归档 等）
- 详细说明（退回原因、附件驳回原因、处理结果等）

失败原因会完整保留，可随时追溯"是谁、什么时候、为什么没处理成功"。

```

├── deno.json                   # Deno + Fresh 配置（端口 3009）
├── dev.ts / main.ts / fresh.config.ts
├── routes/
│   ├── _app.tsx                # 全局布局

└── static/styles.css           # 全局样式
```
