# 备件更换单异常申诉系统

基于 React + Vite + Rust Poem + SQLite 的备件更换单流程管理系统，支持正常登记、核验、复核归档，以及异常申诉的完整闭环。

## 一、目录结构

```
trae-code-3/
├── backend/            # Rust 后端 (Poem + SQLx + SQLite)
│   ├── Cargo.toml
│   ├── .env.example
│   └── src/
│       ├── main.rs     # API 路由与服务入口
│       ├── models.rs   # 数据模型与类型
│       ├── db.rs       # 数据库连接、建表、演示数据
│       └── service.rs  # 业务逻辑：状态机、角色校验、版本控制、证据校验
└── frontend/           # React 前端 (Vite + TypeScript)
    ├── package.json
    ├── vite.config.ts
    ├── tsconfig.json
    ├── index.html
    └── src/
        ├── main.tsx
        ├── App.tsx
        ├── styles.css
        ├── utils.tsx
        ├── api/        # axios 封装

        └── pages/

            └── OrderDetail.tsx  # 详情页（信息、证据、处理记录、操作面板）
```

## 二、角色与办理边界

| 角色 | 人员 | 可办理的操作 |
|---|---|---|
| **备件更换登记员** (registrar) | 张登记员、李登记员 | 创建草稿、提交登记、被退回后申诉提交、被驳回后补正重提、复核退回后补正重提 |
| **备件更换审核主管** (auditor) | 王审核主管 | 核验通过、核验退回补正 |
| **复核负责人** (reviewer) | 赵复核负责人 | 受理申诉、复核确认通过、驳回补正、复核退回补正、归档 |

## 三、流程说明

### 3.1 正常流程

```
草稿(draft)
  ↓ 登记员 提交登记
已登记待核验(registered)
  ↓ 审核主管 核验
核验办理中(verifying) → 核验通过
  ↓
复核办理中(reviewing)
  ↓ 复核负责人 确认/归档
复核确认待归档(review_confirmed) → 已归档(archived)
```

### 3.2 异常申诉流程（重点）

```
核验退回补正(verify_returned)
  ↓ 登记员 提交申诉（可补证据+申诉理由）
申诉已提交(appeal_submitted)
  ├─→ 复核负责人 受理申诉 → 申诉已受理复核中(appeal_accepted)
  │                                     ├─→ 复核确认通过 → 归档
  │                                     ├─→ 复核退回补正(review_returned) → 登记员补正重提
  │                                     └─→ 驳回补正(appeal_rejected_correction)
  │                                                          ↓ 登记员补正重提
  │                                                     申诉补正后重提(appeal_resubmitted)
  │                                                          ↓ 复核
  │                                                     归档 / 再次退回
  └─→ 复核负责人 驳回补正 → appeal_rejected_correction（同上闭环）
```

### 3.3 复核退回补正办理说明

复核负责人在复核过程中可执行**复核退回补正**（`review_returned`），将单据退回登记员补正：

```
复核办理中(reviewing) / 申诉受理(appeal_accepted) / 申诉补正后重提(appeal_resubmitted)
  ↓ 复核负责人 填写退回原因 → 复核退回补正(review_returned)
  ↓ 登记员 补正证据 + 补正说明 → 补正后重新提交复核
申诉补正后重提(appeal_resubmitted)
  ↓ 复核负责人 复核确认 / 再次退回 / 归档
```

与"驳回补正"（`appeal_rejected_correction`）的区别：复核退回补正发生在复核阶段，登记员补正后直接回到复核负责人；驳回补正发生在申诉阶段，登记员补正后重新进入申诉流程。

## 四、后端校验点与失败留痕

每次提交操作，后端都会依次校验以下 5 项，任一项不通过都会**保留原状态 + 写入失败处理记录**（`from_status == to_status`），并在处理记录时间线中标注失败原因：

1. **版本**：请求 `version` 必须等于单据 `version`（乐观锁，防并发冲突）→ 失败记录：`xxx失败-版本冲突`
2. **处理人**：操作者 `handler_id` 必须等于单据 `current_handler_id` → 失败记录：`xxx失败-处理人不匹配`
3. **角色**：操作者角色必须等于单据 `current_handler_role` → 失败记录：`xxx失败-角色不匹配`
4. **状态**：状态必须匹配当前操作允许的前置状态（状态机）→ 失败记录：`xxx失败-状态不允许`
5. **证据**：关键节点（提交、核验通过、复核确认、归档）至少 2 份证据 → 失败记录：`xxx失败-证据不足`
6. **意见**：退回/驳回操作必须填写处理意见 → 失败记录：`xxx失败-意见为空`

> 失败留痕说明：校验失败时单据状态、处理人、版本号均不变，仅在 `process_records` 表新增一条 `from_status == to_status` 的记录，操作人可在详情页处理记录时间线中看到失败原因。

## 五、启动步骤

### 5.1 启动后端（默认端口 8003）

```bash
cd backend

# 首次编译（会下载依赖，首次约 3-8 分钟）
cargo build

# 直接运行（自动建库 + 写入演示数据）
# 方式一：环境变量指定端口
PORT=8003 RUST_LOG=info ./target/debug/spare-part-backend

# 方式二：复制环境变量文件
cp .env.example .env   # 按需修改
cargo run
```

启动成功后：
- API 根路径：`http://localhost:8003/api`
- 健康检查：`http://localhost:8003/api/health`
- SQLite 数据文件：`backend/data.db`（项目本地文件，首次启动自动创建）

> 端口环境变量：后端端口由 `PORT` 环境变量控制（默认 `8003`），日志级别由 `RUST_LOG` 控制（默认 `info`），数据库路径由 `DATABASE_URL` 控制（默认 `sqlite:data.db?mode=rwc`）。可参考 `backend/.env.example`。

### 5.2 启动前端（默认端口 3003）

```bash
cd frontend
npm install
npm run dev
```

打开浏览器访问：`http://localhost:3003`

Vite 已配置代理 `/api` → `http://localhost:8003`，无需跨域处理。

### 5.3 修改端口

**后端端口**：启动时加环境变量 `PORT=8003`（或改 `.env`）

**前端端口**：修改 `frontend/vite.config.ts` 的 `server.port`，同时同步修改代理目标。

```ts
// vite.config.ts
server: {
  port: 3003,  // 改这里
  proxy: {
    '/api': {
      target: 'http://localhost:8003',  // 后端端口同步
      changeOrigin: true,
    },
  },
},
```
