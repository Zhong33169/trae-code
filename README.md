# 酒店集团 - 移动补录校验住客订单系统

## 概述

住客订单补录校验系统，规范住客订单从补录登记 → 过程核验 → 复核归档的全流程，通过角色权限隔离和证据校验机制，防止越权操作、重复补录、缺失证据和覆盖已归档结果。

## 技术栈

- **前端**: Next.js 14 App Router + Tailwind CSS + Zustand（端口 3001）
- **后端**: Node.js + Fastify 4 + sql.js (SQLite WASM) + JWT（端口 8001）
- **数据库**: SQLite（本地文件 data.db）

## 初始化

### 1. 后端

```bash
cd backend
npm install
npm run build
npm run dev
```

后端启动在 http://localhost:8001，首次启动自动初始化数据库并插入种子数据。

### 2. 前端

```bash
cd frontend
npm install
npm run dev
```

前端启动在 http://localhost:3001，自动以 `receptionist1` 登录。

## 业务流程

```
创建订单 → 待补录 → [前厅接待补录登记] → 待核验 → [客房主管核验] → 待复核 → [值班经理归档] → 已归档
                        ↑                    |                     |
                        +---- 退回 ----------+                     |
                                             +----- 退回 ---------+
```

## 后端校验规则（所有规则后端强制执行，返回 403 + 具体原因）

| 校验场景 | 触发条件 | 返回 reason |
|----------|----------|-------------|
| 错角色补录 | 非前厅接待调用 supplement | 仅前厅接待可以补录登记 |
| 错角色核验 | 非客房主管调用 verify | 仅客房主管可以进行过程核验 |
| 错角色归档 | 非值班经理调用 review | 仅值班经理可以进行复核归档 |
| 错误状态 | 订单状态与操作不匹配 | 订单状态不是待补录/待核验/待复核，无法操作 |
| 缺失证据 | 推进时未提供必需证据 | 补录登记/核验通过/归档确认必须至少提供1项证据 |
| 版本冲突 | 提交版本号与当前版本不匹配 | 订单已被他人修改，请刷新后重试（版本冲突） |
| 重复补录 | 订单已有补录审计记录 | 该订单已有补录记录，不可重复补录 |
| 覆盖归档 | 对已归档订单操作 | 已归档订单不可修改 |

## API 接口

### 认证

- `POST /api/auth/login` — 登录，返回 JWT token
- `GET /api/auth/me` — 获取当前用户信息

### 订单

- `GET /api/orders` — 获取订单列表（支持 status 筛选）
- `GET /api/orders/:id` — 获取订单详情（含证据和操作日志）
- `POST /api/orders` — 创建订单（仅前厅接待）
- `PUT /api/orders/:id/supplement` — 补录登记
- `PUT /api/orders/:id/verify` — 过程核验
- `PUT /api/orders/:id/review` — 复核归档
- `POST /api/orders/batch-action` — 批量操作（逐单携带版本号，逐单返回失败原因和错误码）

**批量操作请求格式：**
```json
{
  "orders": [
    { "id": "o1", "version": 1 },
    { "id": "o2", "version": 2 }
  ],
  "action": "supplement",
  "evidenceItems": [{ "type": "身份证扫描", "description": "..." }]
}
```

**批量操作返回格式：**
```json
{
  "successes": [{ "id": "o1", "order_no": "ORD-..." }],
  "failures": [
    { "id": "o2", "order_no": "ORD-...", "reason": "该订单已有补录记录，不可重复补录", "code": "duplicate_supplement" }
  ]
}
```

**失败错误码 (code)：**
| 错误码 | 说明 |
|--------|------|
| `wrong_role` | 角色无权操作 |
| `wrong_status` | 订单状态不匹配 |
| `missing_evidence` | 缺少必需证据 |
| `version_conflict` | 版本冲突（旧版本） |
| `duplicate_supplement` | 重复补录 |
| `archived` | 已归档订单不可修改 |
| `not_found` | 订单不存在 |
| `unknown` | 未知错误 |

## 前端功能

- **订单队列主页**: 60/40 分栏布局，左侧订单列表 + 右侧证据面板
- **角色切换**: 顶部一键切换三个演示角色，自动登录并刷新数据
- **状态筛选**: 全部/待补录/待核验/待复核/已归档
- **批量操作**: 勾选多个订单后底部出现批量操作栏
- **订单详情**: 分步骤进度条 + 动态证据表单 + 校验提示 + 审计日志时间线
- **实时校验**: 后端返回的 403 错误会以红色横幅展示具体原因
