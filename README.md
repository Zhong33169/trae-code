# 续保任务批量变更复核系统

三角色（客户经理 → 核保专员 → 业务负责人）流转线，支持批量变更、失败重试、批量审计。

## 技术栈

| 层 | 技术 |
|---|---|
| 前端 | Angular 18 + @angular/build (Vite/esbuild) · 端口 3005 |
| 后端 | Go 1.22 + Gin + SQLite (modernc.org/sqlite 纯 Go 驱动) · 端口 8005 |
| 数据库 | 本地 SQLite (`backend/data/renewal.db`) |
| 鉴权 | JWT (24h) + bcrypt |

## 快速启动

### 前提

- Go 1.22+
- Node.js 18+ / npm

### 1. 启动后端

```bash
cd backend
go mod tidy
go run .
```

后端启动在 `http://localhost:8005`，自动建表并插入种子数据（3 用户 + 8 续保任务）。

数据库文件：`backend/data/renewal.db`（首次运行自动创建）。

### 2. 启动前端

```bash
cd frontend
npm install
npx ng serve --port 3005
```

前端启动在 `http://localhost:3005`，API 请求代理到后端 `http://localhost:8005`。

## 种子任务样例

| 任务号 | 状态 | 设计目的 |
|--------|------|----------|
| T1 | draft | 正常草稿，客户经理可提交 |
| T2 | submitted | 待核保专员复核 |
| T3 | reviewed | 待业务负责人确认 |
| T4 | confirmed | 待业务负责人归档 |
| T5 | draft | 批量提交候选（与 T1 一起批量） |
| T6 | submitted | 无证据（验证 MISSING_EVIDENCE 拦截） |
| T7 | draft | 缺少登记证据（验证提交前拦截） |
| T8 | archived | 已归档终态（验证 INVALID_STATUS 拦截） |

## 业务流转线

```
客户经理登记 → 提交(草稿→待复核) → 核保专员复核(待复核→待确认) → 业务负责人确认(待确认→已确认) → 业务负责人归档(已确认→已归档)
                                      ↓                                    ↓
                                   可驳回                                可驳回
```

后一岗位不能替前一岗位补流程——后端通过 `FORBIDDEN_ROLE` 拦截。

## 四类校验规则

| 错误码 | HTTP 状态 | 说明 |
|--------|-----------|------|
| FORBIDDEN_ROLE | 403 | 当前角色无权执行该操作 |
| STALE_VERSION | 409 | 乐观锁版本冲突，需刷新 |
| MISSING_EVIDENCE | 422 | 缺少必要证据 |
| INVALID_STATUS | 409 | 任务状态不允许该操作 |

绕过页面直接调用 API 同样受上述校验拦截，返回具体原因。

## 批量变更

- 选择多个任务后执行批量操作，自动生成批次号（格式 `BN-YYYYMMDD-NNNN`）
- 逐项校验，部分成功、部分失败——失败项留在结果中不被吞掉
- 失败项可在批次明细页重试（补充证据后重新提交）
- 每次批量操作生成审计日志

## 页面结构

| 路由 | 页面 |
|------|------|
| `/login` | 登录（角色快速切换） |
| `/` | 续保任务队列（首屏：队列 + 筛选 + 证据侧栏 + 批量操作条） |
| `/tasks/:id` | 任务详情办理（证据时间线 + 角色受限操作 + 流转历史） |
| `/batches` | 批量变更工作台（批次列表） |
| `/batches/:id` | 批次明细（成功/失败项 + 重试 + 审计日志） |
