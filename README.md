# 行政后勤中心 - 会议预约单管理系统

基于真实办理场景的离线台账回填会议预约单系统。覆盖从会议室预约到使用确认的完整流程，支持多角色协作、批次管理、异常处理和审计追踪。

## 技术栈

- **前端**: Lit 3 + Vite 5 (端口: 3008)
- **后端**: Python + Starlette + SQLAlchemy (端口: 8008)
- **数据库**: SQLite (自动初始化种子数据)

## 快速开始

### 1. 启动后端服务

```bash
cd backend
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8008 --reload
```

后端服务启动后会自动初始化数据库并加载种子数据。

### 2. 启动前端服务

```bash
cd frontend
npm install
npm run dev
```

前端服务运行在 http://localhost:3008

### 3. 访问系统

打开浏览器访问 http://localhost:3008

| 会议预约审核主管 | auditor | 李审核 | 审核预约单、退回补正 |

## 业务流程

```
草稿 → 待审核 → 审核通过 → 使用确认 → 复核归档
  ↓         ↓         ↓          ↓
(编辑)    (退回)    (使用)    (退回)
  ↑         ↑         ↑          ↑
退回补正 ──┘         │          │
                      └──────────┘
```

1. **登记员** 创建预约单（草稿状态）
2. **登记员** 提交审核（待审核状态）
3. **审核主管** 审核通过 或 退回补正
4. 审核通过后进入使用准备阶段
5. **登记员** 使用确认（填写使用结果）
6. **复核负责人** 复核通过后归档 或 退回补正

## 核心功能

### 会议预约单管理
- 预约单列表：支持按状态、异常类型筛选，关键词搜索
- 预约单详情：5个Tab页（基本信息、设备准备、附件材料、使用结果、审计备注）
- 新建预约：实时批次校验，自动检测重复批次和状态不一致
- 编辑补正：退回的预约单可由登记员补充材料后重新提交

### 批次管理
- 批次列表：展示所有批次及其处理状态
- 批次详情：查看批次内所有预约单的状态分布
- 异常检测：自动识别批次内状态不一致的情况
- 重复批次检测：新建预约时自动检测批次号是否已存在

### 审计日志
- 全量操作记录：所有状态变更均留痕
- 失败/退回记录：专门筛选失败和退回操作
- 审计详情：记录操作人、角色、时间、状态变更、备注原因

## API 接口

### 预约单接口
- `GET /api/reservations/` - 获取预约单列表
- `GET /api/reservations/statuses` - 获取状态列表
- `GET /api/reservations/exceptions` - 获取异常类型列表
- `POST /api/reservations/` - 创建预约单
- `GET /api/reservations/{id}` - 获取预约单详情
- `PUT /api/reservations/{id}` - 更新预约单
- `DELETE /api/reservations/{id}` - 删除预约单
- `POST /api/reservations/{id}/submit` - 提交审核
- `POST /api/reservations/{id}/audit/pass` - 审核通过
- `POST /api/reservations/{id}/audit/return` - 审核退回
- `POST /api/reservations/{id}/usage-confirm` - 使用确认
- `POST /api/reservations/{id}/review/pass` - 复核通过归档
- `POST /api/reservations/{id}/review/return` - 复核退回

### 批次接口
- `GET /api/batches/` - 获取批次列表
- `GET /api/batches/check` - 检查批次是否存在/状态是否一致
- `GET /api/batches/{batch_no}` - 获取批次内预约单
- `POST /api/batches/status-check` - 批次状态一致性校验

### 审计接口
- `GET /api/audit/` - 获取审计日志
- `GET /api/audit/failures` - 获取失败/退回记录

### 用户接口
- `GET /api/users/` - 获取用户列表
- `GET /api/users/current` - 获取当前用户

## 验收测试要点

1. **正常单流程**: 从草稿→提交→审核通过→使用确认→复核归档，每步状态正确变化
2. **缺材料单**: 审核时退回，登记员补充后重新提交，退回原因在详情页可见
3. **超时单**: 超过会议时间未处理的预约单，状态标记为超时
4. **退回单**: 审核或复核阶段退回，需说明原因，审计日志留痕
5. **重复批次**: 新建时输入已有批次号，系统提示重复并说明线上线下差异
6. **状态不一致**: 批次内存在不同状态预约单时，批次管理页显示警告
7. **批量结果说明**: 批次详情页逐单展示状态，不一致时明确提示
8. **失败原因审计**: 审计日志页可查询所有失败/退回操作，含操作人、时间、原因
