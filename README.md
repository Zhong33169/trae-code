# 政策兑现单管理系统

基于 **前端 Fresh (Preact) + 后端 Node.js + Hono + SQLite** 的政策兑现单全流程管理系统。

## 📋 业务特性

### 角色权限（非隐藏按钮，真实角色切换）
- **政策兑现登记员**（REGISTRAR）：发起兑现单、补正附件、提交审核
- **政策兑现审核主管**（REVIEWER）：审核兑现单、驳回补正、通过审核
- **园区招商中心复核负责人**（APPROVER）：复核通过、退回、归档

### 业务流程
```
草稿 → 发起审核 → 待审核 → 审核通过 → 复核通过 → 归档
                ↓        ↓
              待补正   已退回
                ↓
              补齐附件后重新提交
```

### 核心功能
- ✅ 附件缺失补正流程：补齐附件后才能回到处理队列
- ✅ 被驳回的附件保留驳回原因，支持重新上传
- ✅ 列表支持按状态和异常类型筛选
- ✅ 详情页处理：附件管理、审核结果、退回原因、审计备注
- ✅ 失败原因进入审计日志，可追溯操作人、时间、原因
- ✅ 批量操作支持逐条说明结果

## 🚀 快速开始

### 环境要求
- Node.js >= 18

### 1. 初始化数据库（包含演示数据）
```bash
cd backend
npm install
npm run init-db
```

### 2. 启动后端（端口 8001）
```bash
cd backend
npm run dev
```

### 3. 启动前端（端口 3001）
```bash
cd frontend
npm install
npm run dev
```

### 4. 访问系统
打开浏览器访问：http://localhost:3001

### 正常流程测试（以 ZC2024001 为例）
1. **登记员**登录，查看 ZC2024001 详情，确认附件齐全
2. 切换角色到 **审核主管**，审核通过
3. 切换角色到 **复核负责人**，复核通过并填写办理结果
4. 复核负责人点击「归档」，流程完成

### 附件补正流程测试（以 ZC2024002 为例）
1. **登记员**登录，查看 ZC2024002 详情
2. 查看被驳回附件的驳回原因：「数据与纳税申报表不一致」
3. 添加缺失的附件：「研发费用专项审计报告.pdf」
4. 重新上传被驳回的「研发费用台账.pdf」（选择重新上传）
5. 添加「研发人员清单.pdf」
6. 点击「补正完成，重新提交」，状态回到待审核
7. 切换 **审核主管** 角色，可在待审核列表看到该单

### 超时单处理（ZC2024003）
- 列表页异常标记「超时」，详情页补正截止日期显示红色「已超时」

### 退回单查看（ZC2024004）
- 状态为「已退回」，详情页显示退回原因和审计日志

### 批量操作测试
1. **登记员**登录，新建 2 个草稿兑现单
2. 其中 1 个添加必要附件，另 1 个不添加
3. 列表页勾选 2 个草稿，点击「批量提交审核」
4. 查看批量结果：1 条成功（附件齐全），1 条失败（缺少附件）
5. 失败单会生成审计日志记录失败原因

## 🔍 审计日志

- 顶部导航点击「审计日志」可查看所有操作记录
- 支持「只看失败/异常记录」筛选
- 每条失败记录包含：操作人、角色、时间、失败原因、详细说明

## 🛠️ 技术栈

### 前端
- **Preact** (类 Fresh 轻量架构)
- **React Router** 路由
- **Vite** 构建工具
- 端口：3001

### 后端
- **Node.js** + **TypeScript**
- **Hono** 轻量 Web 框架
- **Better-SQLite3** 数据库
- **bcryptjs** 密码加密
- 端口：8001

### 数据库表结构
- `users` - 用户表（含角色）
- `policy_orders` - 政策兑现单主表
- `attachments` - 附件表（含驳回原因）
- `review_records` - 过程核验记录
- `audit_logs` - 审计日志（失败原因追溯）
