# 幼儿园晨检记录系统（节点超时追踪）

基于 Preact + Vite + Express + SQLite 构建的幼儿园晨检记录管理系统，支持角色权限管理、节点超时追踪、操作日志审计等功能。

## 功能特性

- 🔐 **角色权限管理**：晨检登记员、晨检审核主管、幼儿园复核负责人，各角色可见字段和可执行操作不同
- 📋 **待办队列**：登录后首先看到当前岗位需要处理的队列，而非静态表格
- ⏱️ **节点超时追踪**：登记节点（30分钟）、审核节点（60分钟）、复核节点（120分钟），实时计算超时状态
- 🔄 **完整流程**：登记 → 审核 → 复核归档，支持退回补正/重审并记录异常原因
- 👶 **幼儿档案管理**：幼儿基础信息维护，与晨检记录联动
- 📊 **统计概览**：状态分布、超时统计，列表/详情/统计数据一致
- 📜 **操作日志**：所有状态变更均有完整操作记录，可追溯责任人
- 💾 **本地 SQLite 数据存储**：数据持久化，刷新后数据一致

## 技术栈

- **前端**：Preact 10 + Vite 5 + preact-router
- **后端**：Node.js + Express 4
- **数据库**：SQLite3（better-sqlite3 替代方案）
- **认证**：JWT + bcryptjs

## 快速开始

### 1. 启动后端

```bash
cd backend

# 安装依赖
npm install

# 初始化数据库（创建表 + 样例数据）
npm run init-db

# 启动后端服务
npm start
```

后端默认端口：**3001**

可通过环境变量 `PORT` 修改端口，例如：
```bash
PORT=3001 npm start
```

### 2. 启动前端

```bash
cd frontend

# 安装依赖
npm install

# 启动开发服务器
npm run dev
```

前端默认端口：**3000**

打开浏览器访问：http://localhost:3000

## 业务流程

### 状态流转

```
待登记 (pending_registration)
    │
    ▼ 登记员提交
待审核 (pending_audit)
    │
    ├─► 审核通过 ──► 待复核 (pending_review)
    │                     │
    │                     ├─► 复核通过 ──► 已归档 (archived)
    │                     │
    │                     └── 退回重审 ◄──┐
    │                                     │
    └── 退回补正 (pending_correction) ───┘
           登记员补正后重新提交审核
```

### 节点超时标准

| 节点 | 超时时间 | 责任角色 | 计算起点 |
|------|----------|----------|----------|
| 登记节点 | 30 分钟 | 晨检登记员 | 记录创建时间 |
| 审核节点 | 60 分钟 | 晨检审核主管 | 提交审核时间 |
| 复核节点 | 120 分钟 | 幼儿园复核负责人 | 审核通过时间 |

### 各角色权限

#### 晨检登记员 (registrar)
- 可见：待登记、待补正的队列
- 可操作：创建晨检记录、编辑登记信息、提交审核
- 可见字段：幼儿信息、体温、精神状态、皮肤、咽喉、手足、其他症状、登记备注

#### 晨检审核主管 (auditor)
- 可见：待审核的队列
- 可操作：审核通过、退回补正（需填写异常原因）
- 可见字段：全部登记信息 + 审核意见 + 异常原因

#### 幼儿园复核负责人 (reviewer)
- 可见：待复核的队列
- 可操作：复核归档、退回重审（需填写异常原因）
- 可见字段：全部信息 + 复核意见

## API 接口

### 认证
- `POST /api/login` - 登录

### 幼儿档案
- `GET /api/children` - 获取幼儿列表
- `GET /api/children/:id` - 获取幼儿详情
- `POST /api/children` - 新增幼儿
- `PUT /api/children/:id` - 更新幼儿

### 晨检记录
- `GET /api/records` - 获取记录列表（支持 queue=1 过滤待办）
- `GET /api/records/:id` - 获取记录详情（含超时信息和操作日志）
- `POST /api/records` - 创建记录
- `PUT /api/records/:id/submit-audit` - 提交审核
- `PUT /api/records/:id/audit-pass` - 审核通过
- `PUT /api/records/:id/audit-reject` - 退回补正
- `PUT /api/records/:id/review-pass` - 复核归档
- `PUT /api/records/:id/review-reject` - 退回重审

### 统计
- `GET /api/stats/dashboard` - 获取统计数据

### 操作日志
- `GET /api/logs` - 获取操作日志

## 数据一致性说明

- **后端为唯一真相源**：所有状态变更均由后端计算和存储，前端仅展示
- **操作日志完整**：每次状态变更都记录操作人、角色、前后状态、备注
- **超时实时计算**：列表和详情的超时状态均由后端根据节点进入时间实时计算
- **刷新一致**：刷新页面后，列表数量、详情状态、统计数据、操作记录完全一致
