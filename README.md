# 售后处理工作流系统

基于风险分级处置的售后处理单管理系统，支持三阶段流程（售后退款 → 仓库核实 → 客服回访）和三级角色审批（登记员 → 审核主管 → 复核负责人）。

## 技术栈

- **前端**：Preact + Vite（端口 3004）
- **后端**：Go Echo 框架（端口 8004）
- **数据库**：SQLite（本地文件 `backend/aftersales.db`）

## 快速启动

### 前置条件

- Go 1.21+（需启用 CGO，用于 SQLite 驱动）
- Node.js 18+

### 1. 启动后端

```bash
cd backend
go mod tidy
rm -f aftersales.db        # 首次启动会自动建库并填充样例数据
go run .
```

后端默认监听 `8004` 端口，可通过环境变量修改：

```bash
BACKEND_PORT=9004 DB_PATH=./data.db go run .
```

### 2. 启动前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `3004` 端口，可通过环境变量修改：

```bash
FRONTEND_PORT=5004 BACKEND_PORT=9004 npm run dev
```

### 3. 访问系统

浏览器打开 `http://localhost:3004`

## 端口配置

| 服务 | 默认端口 | 环境变量 |
|------|---------|---------|
| 前端 | 3004 | `FRONTEND_PORT` |
| 后端 | 8004 | `BACKEND_PORT` |

换端口时，前端需同时设置 `FRONTEND_PORT` 和 `BACKEND_PORT`（Vite 代理需要），后端设置 `BACKEND_PORT` 和 `FRONTEND_PORT`（CORS 需要）。

## 工作流说明

### 角色与操作

| 角色 | 可执行操作 | 对应订单状态 |
|------|-----------|------------|
| 售后处理登记员 | 发起处理 / 补正提交 | draft / returned |
| 售后处理审核主管 | 办理通过 / 退回补正 | pending_process |
| 直播电商团队复核负责人 | 复核归档 / 退回补正 | pending_review |

### 流程阶段

每个售后处理单依次经过三个阶段，每个阶段内都走"发起 → 办理 → 复核归档"的审批链：

1. **售后退款**（refund）→ 复核归档后进入下一阶段
2. **仓库核实**（warehouse）→ 复核归档后进入下一阶段
3. **客服回访**（followup）→ 复核归档后工单完成

### 风险分级

- **高风险**（high）：队列中红色左边框标识，支持升级/降级操作
- **中风险**（medium）：橙色标识
- **低风险**（low）：绿色标识

风险等级变更需填写原因，系统自动记录变更日志（含原等级、新等级、原因、操作人、时间），不可只改颜色不留痕。

### 后端提交校验

每次操作提交时，后端依次校验：

1. **订单存在性** → 404
2. **用户存在性** → 400
3. **角色匹配** → 当前用户角色必须与订单 handler_role 一致，否则 403 + 写入"角色不匹配"记录
4. **操作允许性** → 当前状态+角色组合必须支持该操作，否则 400 + 写入"操作不被允许"记录
5. **版本乐观锁** → 提交的版本号必须与当前一致，否则 409 + 写入"版本冲突"记录
6. **必填证据** → 所有操作（发起/补正/办理/复核归档）均校验 required_evidence 必须已提供，否则 400 + 写入"缺少必要证据"记录，附缺失清单

校验失败时**保留原状态、原版本号**，仅写入一条 validation_failed 类型的处理记录。

## API 概览

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/users | 获取用户列表 |
| GET | /api/orders | 获取工单列表（支持 risk_level/stage/status/handler_role 筛选） |
| GET | /api/orders/:id | 获取工单详情（含处理记录和风险变更日志） |
| POST | /api/orders | 新建工单 |
| POST | /api/orders/:id/action | 执行工作流动作 |
| POST | /api/orders/:id/risk | 变更风险等级 |
| PUT | /api/orders/:id/evidence | 更新证据材料 |
| GET | /api/stats | 获取统计数据 |
