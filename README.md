# 连锁药房风险分级处置处方订单系统

基于 **Astro + React Islands** 前端 + **Koa** 后端 + **SQLite** 本地数据库的处方订单风险分级处置系统。

---

## 系统特性

- **三级办理流程**：处方登记员发起/补正 → 处方审核主管审核 → 连锁药房复核负责人复核归档
- **风险分级机制**：高、中、低三级风险，影响队列排序优先级和必填证据要求
- **状态流转校验**：严格校验处理人、角色、状态、版本号和必填证据，校验失败保留原状态并记录
- **完整操作留痕**：每一步操作都有操作记录，详情页可见上一处理人意见和结果
- **多角色视角**：不同角色看到不同的订单队列和操作权限
- **端口可配置**：前后端端口均可通过环境变量修改

## 快速开始

### 1. 环境要求

- Node.js >= 16

### 2. 安装后端依赖并初始化数据库

```bash
cd backend
npm install
npm run init-db
```

执行成功后会在 `backend/data/pharmacy.db` 生成 SQLite 数据库文件，包含 10 条样例处方订单。

### 3. 启动后端服务

```bash
cd backend
npm start
```

后端默认运行在 **8003** 端口。

修改端口：

```bash
# macOS / Linux
PORT=8080 npm start

# Windows (PowerShell)
$env:PORT=8080; npm start
```

### 4. 安装前端依赖

```bash
cd frontend
npm install
```

### 5. 启动前端开发服务

```bash
cd frontend
npm run dev
```

前端默认运行在 **3003** 端口。

修改端口：

```bash
# macOS / Linux
PORT=3000 npm run dev

# Windows (PowerShell)
$env:PORT=3000; npm run dev
```

修改后端 API 端口（前端调用的后端端口）：

```bash
# macOS / Linux
API_PORT=8080 npm run dev

# Windows (PowerShell)
$env:API_PORT=8080; npm run dev
```

## 业务流程

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  处方登记   │────▶│  过程核验   │────▶│  复核归档   │
│  (登记员)   │     │  (审核主管) │     │ (复核负责人)│
└─────────────┘     └─────────────┘     └─────────────┘
       │                   │                   │
       └──── 退回补正 ◀────┘                   │
                             退回补正 / 驳回  │
                        ◀─────────────────────┘
```

### 状态说明

| 状态 | 说明 |
|------|------|
| 草稿 | 登记员刚创建，未提交 |
| 待审核 | 已提交，等待审核主管处理 |
| 审核中 | 审核主管正在处理 |
| 退回补正 | 审核不通过，需要登记员补正 |
| 待复核 | 审核通过，等待复核负责人处理 |
| 复核中 | 复核负责人正在处理 |
| 已归档 | 复核通过，完成归档 |
| 已驳回 | 复核不通过，订单关闭 |
| 已逾期 | 超过截止时间未处理 |

## 风险分级规则

### 风险等级与队列优先级

- **高风险**：队列最优先排序，红色标识，处理时限更紧
- **中风险**：队列中等优先级，橙色标识
- **低风险**：队列最低优先级，绿色标识

### 风险等级与必填证据

| 风险等级 | 必填证据 |
|----------|----------|
| 高风险 | 处方单 + 身份证 + 病历/诊断证明 |
| 中风险 | 处方单 + 身份证 |
| 低风险 | 处方单 |

提交时会校验必填证据，缺少则无法提交并提示缺失项。

## 核心校验规则

每次操作提交时后端会校验：

1. **处理人校验**：确认用户存在且角色匹配
2. **状态校验**：确认当前状态允许执行目标操作
3. **权限校验**：确认用户有操作该订单的权限（门店/角色/归属）
4. **版本校验**：确认提交的版本号与当前版本一致，防止并发冲突
5. **证据校验**：提交审核时校验该风险等级下的必填证据是否齐全

校验不通过时：
- 订单状态保持不变
- 返回具体错误原因
- 操作不会写入日志

## API 接口

所有接口前缀：`/api`

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/orders` | 获取订单列表 |
| GET | `/orders/:id` | 获取订单详情 |
| GET | `/stats` | 获取统计数据 |
| POST | `/orders/:id/actions/:action` | 执行订单操作 |
| GET | `/orders/:id/evidences` | 获取订单证据列表 |
| POST | `/orders/:id/evidences` | 添加证据 |
| DELETE | `/evidences/:id` | 删除证据 |
| POST | `/orders` | 创建订单 |
| PUT | `/orders/:id` | 更新订单基础信息 |
| GET | `/users/current` | 获取当前用户信息 |
| GET | `/users` | 获取所有用户 |
| GET | `/stores` | 获取所有门店 |

### 查询参数示例

```
GET /api/orders?userId=user-aud-1&userRole=auditor&status=pending_audit&riskLevel=high
```
