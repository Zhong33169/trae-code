# 投诉工单管理系统

服务投诉工单实际流转系统，包含投诉工单登记、过程核验、复核归档全流程。

## 技术栈

- **前端**: React 18 + Vite
- **后端**: Rust + Actix Web
- **数据库**: SQLite（文件存储，开箱即用）
- **前端端口**: 3005
- **后端端口**: 8005

## 角色说明

系统包含三种角色，可在顶部导航栏切换：

| 角色 | 用户名 | 密码 | 职责 |
|------|--------|------|------|
| 投诉登记员 | registrar1 | 123456 | 发起工单、补正退回工单 |
| 投诉审核主管 | auditor1 | 123456 | 办理工单、退回补正、提交复核 |
| 复核负责人 | reviewer1 | 123456 | 复核归档、复核退回 |

## 工单状态流转

```
草稿 ──提交──▶ 待审核 ──开始办理──▶ 办理中 ──提交复核──▶ 待复核 ──归档──▶ 已归档
   ▲                │                │                │
   │                │退回            │退回            │退回
   └────补正重提────┴────────────────┴────────────────┘
```

## 快速开始

### 启动后端

```bash
cd backend
cargo run
```

后端服务启动在 `http://localhost:8005`

### 启动前端

```bash
cd frontend
npm install
npm run dev
```

前端服务启动在 `http://localhost:3005`

首次启动时，数据库会自动创建并初始化演示数据。

## 功能模块

### 1. 投诉工单登记

- 投诉登记员可新建工单
- 填写标题、投诉人、联系方式、优先级、截止时间、投诉内容
- 提交后进入"待审核"状态

### 2. 过程核验

- **审核主管**：领取工单开始办理 → 填写处理结果 → 提交复核
  - 也可退回给登记员补正（需填写退回原因）
- **登记员**：收到退回工单后，补充材料 → 补正后重新提交

### 3. 复核归档

- **复核负责人**：审核处理结果
  - 通过则归档，工单状态变为"已归档"
  - 不通过则退回，工单状态变为"退回补正"

### 4. 离线台账回填

- 支持批量导入线下工单数据
- 记录导入批次、来源和差异
- **防静默覆盖**：
  - 工单号已存在且内容一致 → 标记为"重复"，不覆盖
  - 工单号已存在但状态/内容不一致 → 标记为"冲突"，不覆盖
  - 工单号不存在 → 正常导入
- 批量结果逐条说明，每条记录状态和原因

### 5. 审计日志

- 所有操作均记录审计日志
- 失败操作单独标记，包含失败原因
- 可按工单查看操作历史
- 可追溯：谁、什么时候、做了什么、为什么失败

### 6. 附件管理

- 工单详情页可上传/查看/删除附件
- 支持多附件上传
- 记录上传人和上传时间

## 验收测试场景

可按以下场景验证系统功能：

### 场景一：正常单全流程

1. 切换到**投诉登记员**，新建一个工单
2. 切换到**投诉审核主管**，点击"开始办理"→填写处理结果→"提交复核"
3. 切换到**复核负责人**，点击"复核归档"
4. 查看审计日志，确认每一步都有记录

### 场景二：缺材料退回补正

1. 切换到**投诉审核主管**，打开 TS202606005
2. 查看退回原因，了解缺材料情况
3. 切换到**投诉登记员**，点击"补正后重提"
4. 工单回到"待审核"状态，形成闭环

### 场景三：超时单

1. 工单列表筛选"仅异常"
2. 查看 TS202606006，异常原因为"工单已超时未处理"
3. 可由审核主管开始办理

### 场景四：复核退回

1. 切换到**复核负责人**，打开 TS202606007
2. 查看退回原因："第一次审核通过，但复核认为处理力度不够"
3. 退回后由审核主管重新办理

### 场景五：离线台账回填

1. 进入"离线台账回填"页面
2. 点击"生成示例数据"
3. 点击"开始导入"
4. 查看导入结果：
   - 成功：2条新工单
   - 重复：1条（TS202606001已存在）
   - 冲突：1条（TS202606002状态不一致）
5. 切换到"导入历史"标签，查看批次详情
6. 查看审计日志，确认导入操作已记录

## API 接口

### 认证

- `POST /api/auth/login` - 登录
- `POST /api/auth/logout` - 登出
- `GET /api/auth/me` - 获取当前用户

### 工单

- `GET /api/tickets` - 工单列表（支持 status、is_exception、keyword 筛选）
- `POST /api/tickets` - 创建工单
- `GET /api/tickets/{id}` - 工单详情
- `PUT /api/tickets/{id}` - 更新工单
- `POST /api/tickets/{id}/process` - 开始办理
- `POST /api/tickets/{id}/submit-review` - 提交复核
- `POST /api/tickets/{id}/return` - 退回
- `POST /api/tickets/{id}/resubmit` - 重新提交
- `POST /api/tickets/{id}/archive` - 归档

### 附件

- `GET /api/tickets/{id}/attachments` - 附件列表
- `POST /api/tickets/{id}/attachments` - 上传附件
- `DELETE /api/tickets/{tid}/attachments/{aid}` - 删除附件

### 审计

- `GET /api/tickets/{id}/audit-logs` - 工单审计日志
- `GET /api/audit-logs` - 全部审计日志
- `GET /api/audit-logs/failures` - 失败日志

### 离线导入

- `POST /api/import` - 批量导入
- `GET /api/import/batches` - 批次列表
- `GET /api/import/batches/{id}` - 批次详情
- `GET /api/import/batches/{id}/records` - 批次明细

## 注意事项

- 数据库文件在 `backend/data/complaint.db`，删除后重启会重新初始化
- 附件上传目录在 `backend/uploads/`
- CORS 已配置放行 `http://localhost:3005`
- 前端通过 Vite 代理 `/api` 和 `/uploads` 到后端 8005 端口
