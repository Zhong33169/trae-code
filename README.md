# 软件外包项目组 - 风险分级处置需求交付单系统

## 项目概述

本系统用于管理软件外包项目的需求交付单全生命周期流转，通过风险分级机制（高/中/低）驱动队列优先级和处理动作差异，确保每一步推进或退回都有明确的意见记录和完整可追溯性。

## 技术栈

- **前端**: React 18 + TypeScript + Vite + Tailwind CSS + Zustand
- **后端**: Python 3.10+ + Django 4.2 + Django Ninja 1.1
- **数据库**: SQLite（本地文件存储）
- **端口**: 前端 3007，后端 8007（均可配置）

## 快速开始

### 1. 环境准备

确保已安装：
- Python 3.10+
- Node.js 18+
- npm 或 pnpm

### 2. 后端启动

```bash
# 进入后端目录
cd backend

# 安装依赖
pip install -r requirements.txt
# 注：macOS 如遇 PEP 668 限制，可加 --break-system-packages 参数
# pip install --break-system-packages -r requirements.txt

# 初始化数据库（建表 + 创建用户 + 样例数据）
python scripts/init_db.py

# 启动后端服务（默认 8007 端口）
python manage.py runserver 0.0.0.0:8007
```

后端启动后，访问 http://localhost:8007/api/docs 可查看 Swagger API 文档。

### 3. 前端启动

```bash
# 进入前端目录
cd frontend

# 安装依赖
npm install

# 启动开发服务器（默认 3007 端口）
npm run dev
```

前端启动后，访问 http://localhost:3007 即可使用系统。

### 4. 修改端口

**修改前端端口**: 编辑 `frontend/vite.config.ts` 中的 `server.port`

**修改后端端口**: 
- 编辑 `backend/.env` 中的 `PORT` 变量
- 启动命令也可以直接指定：`python manage.py runserver 0.0.0.0:8007`

**修改代理**: 如果后端端口变了，编辑 `frontend/vite.config.ts` 中 `server.proxy['/api'].target`

## 核心业务流程

### 三阶段流转

```
登记员发起 → [需求确认] → 审核主管办理 → [排期评估] → 审核主管办理 → [交付验收] → 复核负责人归档
                ↓ 退回补正              ↓ 退回补正                ↓ 退回补正
              登记员补正              登记员补正                登记员补正
```

### 风险分级机制

| 风险等级 | 队列优先级 | 证据要求 | 处理时限 |
|----------|------------|----------|----------|
| 高风险 | 100（置顶） | 至少 3 份，需包含文档和链接 | 1-2 天 |
| 中风险 | 50（正常） | 至少 2 份，需包含文档 | 2-3 天 |
| 低风险 | 10（延后） | 至少 1 份 | 3-5 天 |

### 后端校验规则

每次提交操作时，后端会校验：
1. **处理人校验**：当前用户是否有权限处理该阶段
2. **状态校验**：当前状态是否允许执行该操作
3. **版本校验**：乐观锁，防止并发操作冲突
4. **证据校验**：根据风险等级校验证据数量和类型

校验不通过时：保留原状态，写操作记录，返回错误信息。

## 功能模块

### 工作台首页
- 统计卡片：待办总数、我的待办、已逾期、高风险数量
- 各阶段分布进度条
- 风险分布统计
- 最近需求列表

### 需求队列
- 按阶段、风险、状态筛选
- 关键词搜索
- 优先级排序（高风险在前、逾期优先）
- 分页浏览

### 需求详情
- 基本信息展示
- 三阶段流程进度条
- 处理历史时间线（含操作人、意见、证据）
- 操作区（根据角色和状态显示可用操作）
- 证据材料管理

### 操作记录
- 全量操作日志列表
- 按操作类型筛选
- 完整的状态变更追溯

## API 接口

### 认证
- `POST /api/auth/login` - 用户登录
- `GET /api/auth/me` - 获取当前用户

### 需求交付单
- `GET /api/tickets` - 获取需求列表
- `GET /api/tickets/{id}` - 获取需求详情
- `POST /api/tickets` - 创建需求
- `PUT /api/tickets/{id}/action` - 执行操作

### 统计
- `GET /api/stats/dashboard` - 工作台统计

### 操作记录
- `GET /api/logs` - 获取操作记录

详细 API 文档请启动后端后访问 `/api/docs`。
