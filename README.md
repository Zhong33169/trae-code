# 物业服务中心 · 附件缺失补正报修工单系统

专门面向物业服务中心的报修工单管理系统。不做成泛用待办，完整落地：
- **报修登记员** 发起工单、退回补正上传附件
- **报修审核主管** 审核派单、退回/驳回
- **物业服务中心复核负责人** 复核归档、回访

---

## 📐 工程技术栈

| 层级 | 技术 | 端口 |
|------|------|------|
| 前端 | **Solid.js + Vite** | **3001** |
| 后端 | **Python + Starlette (ASGI)** | **8001** |
| 数据库 | **SQLite**（文件：`backend/repair_system.db`）| - |
| 认证 | JWT (python-jose + bcrypt) | - |
| 跨域 | 后端 CORS 放行 `http://localhost:3001` | - |

- 前端 API 请求基础地址：`http://localhost:8001`
- 后端 CORS 已放行前端端口，前后端可直接联调

## 🚀 快速启动

### 1. 后端（端口 8001）

```bash
cd backend

# 安装依赖（建议 Python 3.10+）
pip install -r requirements.txt

# 初始化数据库并载入种子数据（首次自动执行；也可手动）
python seed_data.py

# 启动服务
python app.py
```

启动后访问：`http://localhost:8001/health` 应返回 `{"status":"ok"}`

**注意**：首次启动 `python app.py` 会自动建库并执行种子初始化，无需手动运行 seed。

---

### 2. 前端（端口 3001）

```bash
cd frontend

# 安装依赖
npm install

# 启动开发服务器
npm run dev
```

启动后访问：`http://localhost:3001`

### ✅ 样例 1：正常工单（待审核）— A栋302厨房水管漏水
- **编号**：`RPxxxxxxx0001`
- **状态**：`待审核`（PENDING_REVIEW）
- **特征**：2 张**必填**现场照片（无驳回、无补传）
- **验收流程**：
  1. 以 `supervisor01`（审核主管）登录 → 进详情 → **审核通过** → 状态变「审核通过」
  2. 继续以主管 → **派单处理** → **开始维修** → **登记完工**（填写维修结果）
  3. 切换到 `reviewer01`（复核负责人） → **复核归档**（填复核意见 + 回访评价）
  4. 最终状态：`已归档`，流转记录完整 5 条
- **审计验证**：审计日志页应看到上述每一步，均为「成功」

### 🧾 样例 2：缺材料退回补正单 — B栋501客厅空调不制冷
- **编号**：`RPxxxxxxx0002`
- **状态**：`待补正`（REVISION_REQUIRED）
- **特征**：

## 🗂️ 附件标记说明（系统重点）

每个附件均有独立状态，不是只算数量：

| 标记 | 颜色 | 含义 |
|------|------|------|
| **必填** | 蓝色标签 | 登记时必须提交的原始报修材料 |
| **补传** | 黄色标签（浅黄色背景） | 退回补正后补充上传的材料 |
| **驳回** | 红色标签（浅红色背景） | 主管审核时判定不合格的附件，附**驳回原因字段** |

- 每个附件可独立查看：文件大小、上传人、上传时间、MIME 类型
- 审核主管角色在「待审核 / 待补正」状态下，可对每个附件执行：
  - 标记必填 / 标记补传 / 驳回附件（需填原因）/ 解除驳回
- 提交审核时系统校验：至少 1 个「必填且未驳回」的附件，否则拦截并记入**失败审计**

## 📋 状态流转（严格按角色权限）

```
草稿 (DRAFT) — 登记员提交 → 待审核 (PENDING_REVIEW)
  ├─ 主管审核通过 → 审核通过 (REVIEW_PASSED) → 派单 (ASSIGNED) → 维修中 (IN_PROGRESS) → 待复核 (COMPLETED) → 复核人归档 (ARCHIVED)
  ├─ 主管退回补正 → 待补正 (REVISION_REQUIRED) — 登记员补正 → 待审核 (PENDING_REVIEW)
  └─ 主管驳回 → 已驳回 (REJECTED) [终止态]
```

**每个流转节点**均：
1. 后端 API 层校验角色权限（不是只藏前端按钮）— 非授权角色 403
2. 写入 `work_order_logs` 流转记录（from/to/status、操作人、备注）
3. 写入 `audit_logs` 审计日志（失败时写入 failure_reason 字段）

## 🔍 审计日志

**路径**：左侧菜单「🔍 审计日志」

- 支持按工单ID、成功/失败过滤
- **失败条目**（红色行）会显示：
  - 操作人（谁）
  - 操作时间（什么时候）
  - failure_reason（**为什么没处理成功**）- 关键信息
- 点击「查看工单 #id」可直接跳转到对应工单详情

## 🐛 常见问题

1. **前端请求被 CORS 拦截**
   确认后端 app.py 中 CORSMiddleware allow_origins 包含 `http://localhost:3001`，且后端启动在 8001

2. **数据库需要重建**
   删除 `backend/repair_system.db`，然后重启后端（自动重建+seed），或执行 `python backend/seed_data.py`

3. **Token 过期（默认 24 小时）**
   重新登录即可
