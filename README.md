# 换表申请管理系统

换表申请全流程管理系统，覆盖申请登记、过程核验、复核归档等环节，支持角色权限、异常检测、审计日志等功能。

## 技术栈

- **前端**: TanStack Start (React)，端口 3004
- **后端**: Node.js + Hono，端口 8004
- **数据库**: SQLite (better-sqlite3)

## 目录结构

```
├── backend/              # 后端项目
│   ├── src/
│   │   ├── db/           # 数据库相关

│   │   ├── routes/       # API 路由
│   │   ├── utils/        # 工具函数
│   │   └── index.js      # 后端入口
│   └── data/             # SQLite 数据文件目录

│   └── app/
│       ├── routes/       # 页面路由
│       ├── components/   # 组件
│       ├── lib/          # 工具库

```

## 快速开始

### 1. 启动后端

```bash
cd backend
npm install
npm run init-db   # 初始化数据库和演示数据
npm run dev       # 启动开发服务器 (端口 8004)
```

后端 API 地址: `http://localhost:8004/api`

### 2. 启动前端

```bash
cd frontend
npm install
npm run dev       # 启动开发服务器 (端口 3004)
```

前端访问地址: `http://localhost:3004`

## 系统角色

| 角色 | 用户名 | 权限 |
|------|--------|------|
| 换表登记员 | meter_operator (张三) | 发起/补正申请、上传附件 |
| 换表审核主管 | meter_supervisor (李四) | 审核通过/退回、上传附件 |
| 燃气服务公司复核负责人 | gas_archivist (王五) | 复核归档、批量归档、上传附件 |

在页面右上角可切换当前登录角色。

## 业务流程

```
换表登记员发起申请 → 待审核主管办理
    ↓
换表审核主管审核
    ├─ 通过 → 待复核负责人归档
    └─ 退回 → 待登记员补正（可重新提交）
    ↓
燃气服务公司复核负责人复核归档 → 已归档（完成）
```

1. **APP001** - 待登记员操作

   - 状态: 待登记员补正（可提交审核）
   - 离线台账: 已匹配

2. **APP002** - 待复核归档
   - 批次号: BATCH202501001
   - 状态: 待复核负责人归档
   - 离线台账: 已匹配
   - 操作: 切换到 gas_archivist 角色，点击「复核归档」

3. **APP005** - 已完成归档
   - 批次号: BATCH202501003
   - 状态: 已归档
   - 可在审计日志中查看完整流程

### 异常样例

1. **APP003** - 已退回单
   - 批次号: BATCH202501002
   - 状态: 待登记员补正
   - 退回原因: 缺少旧表照片
   - 操作: 在详情页「流程记录」中可查看退回原因；切换到 meter_operator 可补正提交

2. **APP004** - 离线台账缺失
   - 批次号: BATCH202501004
   - 旧表号: OLD-004
   - 离线台账中**不存在**此批次+表号的记录
   - 操作: 走完全流程后，在复核归档时系统会检测到台账缺失，提示失败原因并记录到审计日志

3. **重复批次测试**
   - 新建申请时使用已归档批次号（如 BATCH202501003）但不同旧表号
   - 归档时系统会检测到批次号重复冲突

## 核心功能

### 1. 申请列表
- 按状态筛选（待登记员补正/待审核主管办理/待复核负责人归档/已退回/已归档）
- 按异常筛选（仅显示有问题的申请）
- 按批次号、关键词搜索
- 异常申请行高亮显示（红色背景）
- 批量归档（仅复核负责人角色可见）

### 2. 申请详情
- 基本信息、表计信息展示
- **经办人员展示**: 清晰显示换表登记员（发起）、换表审核主管（办理）、燃气服务公司复核负责人（归档）三个角色及其处理人
- 附件管理: 上传、删除
- 流程记录: 时间线展示每个节点的操作人、角色、意见、退回原因、处理结果
- **离线台账回填失败原因**: 若归档时台账校验失败，在详情页顶部红色提示框显示
- **审计备注**: 可编辑，在详情页显示
- **审计日志**: 记录所有操作，包含失败原因

### 3. 异常校验机制
- **离线台账缺失检测**: 归档时校验批次号+旧表号是否在离线台账中存在
- **批次号重复检测**: 同一批次号被不同表号使用时报警
- 校验失败时:
  - 弹窗提示具体错误信息（说明线上/线下哪里对不上）
  - 可选择「强制归档」继续流程
  - 失败原因记录到申请详情和审计日志

### 4. 批量归档
- 复核负责人可在列表页勾选多条申请批量归档
- 结果弹窗逐条说明：成功/台账匹配成功、失败/台账匹配失败原因
- 批量操作记录到审计日志

### 5. 审计日志
- 独立页面查看所有操作记录
- 支持筛选仅显示失败记录
- 每条记录包含: 操作人、角色、操作类型、关联申请、详情、失败原因
- 可追溯谁、在什么时候、为什么处理失败

## API 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/health | 健康检查 |
| GET | /api/users | 获取用户列表 |
| GET | /api/applications | 获取申请列表（支持 status/abnormal/batch_no/keyword 参数） |
| GET | /api/applications/:id | 获取申请详情 |
| POST | /api/applications | 新建申请（登记员） |
| POST | /api/applications/:id/submit | 提交审核/补正提交（登记员） |
| POST | /api/applications/:id/approve | 审核通过（主管） |
| POST | /api/applications/:id/reject | 退回申请（主管，需 reject_reason） |
| POST | /api/applications/:id/archive | 复核归档（负责人，支持 force_archive） |
| POST | /api/applications/batch-archive | 批量归档（负责人） |
| POST | /api/applications/:id/attachments | 上传附件 |
| DELETE | /api/applications/:id/attachments/:attachId | 删除附件 |
| POST | /api/applications/:id/audit-remark | 更新审计备注 |
| GET | /api/applications/validate/ledger | 校验离线台账（batch_no, old_meter_no 参数） |
| GET | /api/audit | 获取审计日志 |
| GET | /api/audit/failures | 获取失败审计日志 |

所有接口需在请求头中携带 `X-User-Id` 指定当前用户 ID。
