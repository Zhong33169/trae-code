# 政策兑现单管理系统

基于 **前端 Fresh (Preact) + 后端 Node.js + Hono + SQLite** 的政策兑现单全流程管理系统。

## 📋 业务特性

### 角色权限（非隐藏按钮，真实角色切换）
- **政策兑现登记员**（REGISTRAR）：发起兑现单、补正附件、提交审核
- **政策兑现审核主管**（REVIEWER）：审核兑现单、驳回补正、通过审核
- **园区招商中心复核负责人**（APPROVER）：复核通过、退回、归档

### 业务流程
```
草稿 → 发起审核 → 待审核 → 审核通过 → 复核通过 → 归档
                ↓        ↓
              待补正   已退回
                ↓
              补齐附件后重新提交
```

### 核心功能
- ✅ 附件缺失补正流程：补齐附件后才能回到处理队列
- ✅ 被驳回的附件保留驳回原因，支持重新上传
- ✅ 列表支持按状态和异常类型筛选
- ✅ 详情页处理：附件管理、审核结果、退回原因、审计备注
- ✅ 失败原因进入审计日志，可追溯操作人、时间、原因
- ✅ 批量操作支持逐条说明结果

## 🚀 快速开始

### 环境要求
- Node.js >= 18

### 1. 初始化数据库（包含演示数据）
```bash
cd backend
npm install
npm run init-db
```

### 2. 启动后端（端口 8001）
```bash
cd backend
npm run dev
```

### 3. 启动前端（端口 3001）
```bash
cd frontend
npm install
npm run dev
```

### 4. 访问系统
打开浏览器访问：http://localhost:3001

### 正常流程测试（以 ZC2024001 为例）
1. **登记员（registrar）** 登录，查看 ZC2024001 详情，「必备附件清单」卡片显示 4/4 全部完成
2. 顶部下拉切换角色到 **审核主管（reviewer）**，点击「审核通过」
3. 切换角色到 **复核负责人（approver）**，点击「复核通过」并填写办理结果
4. 复核负责人点击「归档」，流程完成，状态变为「已归档」

### 附件补正 + 驳回附件重新上传流程（ZC2024002 核心演示）

> **入口**：详情页「🏷️ 必备附件清单」卡片，每个必备清单分组显示当前有效版本 + 历史驳回/已作废版本。

1. **登记员** 登录，打开 ZC2024002 详情
2. 查看必备附件清单分组：
   - ✅ 营业执照：v1 有效
   - ❌ 研发费用台账：v1 显示**红色「已驳回」徽章** + 驳回原因「数据与纳税申报表不一致…」+ 「🔄 重新上传被驳回附件」按钮
   - ⚠️ 研发费用专项审计报告：未上传
   - ⚠️ 研发人员清单：未上传
3. 点击「研发费用专项审计报告」右侧的「➕ 上传」，补充第一个缺失附件
4. 点击「研发人员清单」右侧的「➕ 上传」，补充第二个缺失附件
5. 点击「研发费用台账」下方的 **「🔄 重新上传被驳回附件」按钮**（附件重传入口）：
   - 原 v1 附件状态变为 **「已作废（已替换）」**（SUPERSEDED）
   - **驳回原因字段保留不清除**（历史可追溯）
   - 新上传 v2 附件版本号 +1，状态为「有效」，`parent_id` 指向 v1
6. 此时必备清单显示 4/4 全部完成，按钮文案从「还差 3 个必备附件」变为「补正完成，重新提交」
7. 点击提交，状态 **从「待补正」（PENDING_CORRECTION）回到「待审核」（PENDING_REVIEW）** ✅
8. 切换 **审核主管** 角色，在待审核列表可看到 ZC2024002

## 🛠️ 技术栈

### 前端
- **Preact** (类 Fresh 轻量架构)
- **React Router** 路由
- **Vite** 构建工具
- 端口：3001

### 后端
- **Node.js** + **TypeScript**
- **Hono** 轻量 Web 框架
- **Better-SQLite3** 数据库
- **bcryptjs** 密码加密
- 端口：8001

### 数据库表结构
- `users` - 用户表（含角色字段）
- `policy_orders` - 政策兑现单主表（含状态、异常类型、退回原因、审计备注）
- `required_attachment_defs` - **必备附件清单表**：每个兑现单定义必传材料名及排序
- `attachments` - 附件表：含 `required_def_id`（关联清单）、`parent_id`（版本链）、`att_status`（ACTIVE/REJECTED/SUPERSEDED）、`version`、`reject_reason`
- `review_records` - 过程核验记录
- `audit_logs` - 审计日志（所有失败操作都写入，含操作人/角色/时间/失败原因/详情）

## 🌐 API 接口（所有非登录接口需请求头 `X-User-Id`）

| 方法 | 路径 | 允许角色 | 说明 |
|------|------|----------|------|
| POST | `/api/auth/login` | 公开 | 登录 |
| GET | `/api/auth/users` | 全部角色 | 获取所有用户（角色切换下拉） |
| POST | `/api/auth/switch-role` | 全部角色 | 切换当前角色 |
| GET | `/api/orders` | 全部角色 | 获取兑现单列表 |
| GET | `/api/orders/:id` | 全部角色 | 获取兑现单详情（含必备清单/分组附件/核验/审计） |
| POST | `/api/orders` | 登记员 | 新建兑现单（可同时传入 `requiredAttachmentNames`） |
| PUT | `/api/orders/:id` | 登记员 | 编辑草稿兑现单 |
| DELETE | `/api/orders/:id` | 登记员 | 删除草稿兑现单 |
| POST | `/api/orders/batch-result` | 登记员 | 批量提交（逐条校验+逐条写审计） |
| POST | `/api/attachments` | 登记员 | 添加附件（关联 `requiredDefId`） |
| **POST** | **`/api/attachments/:id/reupload`** | **登记员** | **🔄 重新上传被驳回附件：旧版 SUPERSEDED + 保留 reject_reason + 新版 version+1** |
| POST | `/api/attachments/:id/reject` | 审核主管 | 驳回附件（写审计） |
| DELETE | `/api/attachments/:id` | 登记员 | 删除草稿附件 |
| GET | `/api/attachments/required-defs/:orderId` | 全部角色 | 获取兑现单的必备附件清单（含完成状态） |
| POST | `/api/review/submit` | 登记员 | 草稿 → 提交审核 |
| POST | `/api/review/correction/submit` | 登记员 | 待补正 → 补齐附件后回到待审核 |
| POST | `/api/review/review/approve` | 审核主管 | 审核通过 |
| POST | `/api/review/review/reject` | 审核主管 | 审核驳回 → 待补正 |
| POST | `/api/review/approver/approve` | 复核负责人 | 复核通过 |
| POST | `/api/review/approver/reject` | 复核负责人 | 复核退回 |
| POST | `/api/review/approver/archive` | 复核负责人 | 归档 |
| GET | `/api/audit` | 全部角色 | 获取审计日志 |
| GET | `/api/audit/failures` | 全部角色 | 获取失败审计日志 |

> 越权访问返回 **HTTP 403** + `{ "error": "权限不足，需要角色：xxx" }`；未登录返回 **HTTP 401**。
